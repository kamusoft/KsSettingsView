## Context

android/ADR-0021 は、ライブラリ既定の ID を持つ `KsSettingsView` が同一階層に複数あるとき、保存先が衝突して状態が混ざるとして、View インスタンス状態の保存も復元もしない縮退条件を置いた。後から加わったスクロール位置の保持も同じ保存状態に載り、同じ条件に従う。判定は window の階層全体で既定 ID の View を数える。

この条件は実測ではなく、防御側に倒して入れたものだった。当時のスパイクが測ったのは、View 直置きと Compose の `AndroidView` のそれぞれ 1 インスタンスだけで、複数を置いた構成は測っていない。

0.1.0-beta.9 で、Composable の `KsSettingsView` を複数の画面で使うアプリ (Navigation Compose) から、別の画面へ進んで戻ったとき・タブを切り替えて戻ったときに、スクロール位置が先頭に戻ると報告された。Composable は View に ID を付けないため、置いた View はすべて既定 ID になる。画面遷移の途中やタブの構成で 2 つが階層に居合わせると、縮退条件に当たる。

一方、状態が混ざるのは、同じ入れ物 (`saveHierarchyState` に渡される 1 つの `SparseArray`) へ同じ ID で書くときだけである。Compose の `AndroidView` は、置いた View ごとに別の入れ物へ保存し、Activity からの保存の走査を自分より下へ通さない (Compose UI 1.11.4 で確認)。AndroidX Fragment も、Fragment の View ごとに同じ形で入れ物を分ける (Fragment 1.8.9 で確認)。これらのホストでは、既定 ID の View が階層にいくつ居合わせても保存先は衝突しない。

前提: 入れ物を分けるホストは、分けた範囲の根に「親からの保存を受けない」設定 (`isSaveFromParentEnabled = false`) を付ける。Compose の `AndroidView` と AndroidX Fragment はこの形を取る。

## Decision

既定 ID の View Host が複数あるかは、window の階層全体ではなく、保存の入れ物を共有する範囲で数える。

android/ADR-0021 の決定のうち、縮退条件の範囲 (「ライブラリ既定 ID のインスタンスが同一階層に複数ある構成では復元しない」) を本決定で置き換える。他の決定 (View インスタンス状態での保存・既定 ID の自前付与・復元の成立条件・保存と閉じの分離) は維持する。

- 範囲の境目は、ホストが入れ物を分けるときに付ける Android 標準の設定 (親からの保存を受けない) で見分ける。境目が無ければ階層全体が範囲で、従来と同じ数え方になる
- 同じ入れ物の中に既定 ID の View Host が複数ある構成は、従来どおり保存も復元もしない。ホストが個別の ID を与えれば成立する点も変えない
- 対象は、この保存状態に載るものすべて (カレンダー選択面の状態とスクロール位置) とする
- Composable だけの特例にはしない。混ざる条件は「同じ入れ物へ書くこと」であって、ホストの種類ではないためである

## Alternatives Considered

- **Composable で置いた View だけ判定から外す**: 変更は最小だが、理由が「Compose だから」になり、混ざる本当の条件を表さない。Fragment ごとに置いた View Host や、利用者が自分で `AndroidView` に包んだ View Host に同じ落ち方が残る。却下。
- **Composable に、利用者が ID か保存のキーを渡す引数を足す**: 入れ物が既に分かれているのに、利用者へ全画面の作業を求め、公開 API も増える。android/ADR-0021 が採った「ホスト側の追加作業なしで成立させる」方向とも逆になる。却下。
- **挙動を変えず、保存しない条件を文書に正しく書く**: 設定画面が 2 つ以上あるアプリで、位置の保持が効かないまま残る。却下。

## Consequences

- 正: Composable の `KsSettingsView` を複数の画面・タブで使うアプリで、利用者の追加作業なしに、スクロール位置とカレンダー選択面の状態が保存・復元される。
- 正: 1 画面に Composable を複数置いた構成も、それぞれが別の入れ物を持つため保存・復元される。
- 正: Fragment ごとに置いた View Host と、利用者が自分で `AndroidView` に包んだ View Host も、同じ理由で成立する。
- 正: 公開 API を変えない。
- 負: 範囲の見分けを Android 標準の設定に頼る。この設定を付けずに独自の入れ物へ保存するホストでは、従来どおり階層全体で数えるため保存されず、個別の ID の付与が要る。
- 負: この設定を付けたうえで、複数の範囲を 1 つの入れ物へ保存するホストがあれば、状態が混ざり得る。
- 負: 0.1.0-beta.9 までと保存の成否が変わる構成がある (1 画面に Composable を複数置いた構成は「保存しない」から「保存する」へ変わる)。

## Revisit When

- Compose の `AndroidView` または AndroidX Fragment が、View ごとに入れ物を分ける形か、「親からの保存を受けない」設定をやめたとき
- 入れ物を分けているのにこの設定を付けないホスト、または設定を付けたまま入れ物を共有するホストで、保存されない・状態が混ざるという報告が出たとき
