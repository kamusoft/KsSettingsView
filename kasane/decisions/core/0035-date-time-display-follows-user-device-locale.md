## Context

日付・時刻を扱う Cell では、選択面と Cell 右側の自動生成値が同じ利用者設定を反映しない状態が観測された。日本語環境の Native iOS では `TimePickerCell` の選択面と右側値が英語表記になり、`DatePickerCell` のホイールも英語月名になった。一方、同じデモの MAUI iOS と Android の選択面は日本語表記になった。

Android で言語を英語へ切り替えた場合は、`TimePickerCell` の選択面が `AM / PM` へ変わった一方、Cell 右側値は `午後` のまま残った。プラットフォームや表示面ごとに Locale の解決時点やキャッシュ寿命が異なり、同じ Cell 内でも言語・地域が分裂している。

Apple のアプリ有効 Locale は、端末の言語・地域だけでなく OS が提供するアプリ単位の言語設定と、アプリが提供すると宣言した localization も考慮する。このため、アプリが日本語の翻訳資源を宣言していない場合、端末が日本語でも picker が英語へフォールバックし得る。しかし、このライブラリの日付・時刻表示には、OS のアプリ単位言語設定があればそれを優先し、なければ端末全体で選択された言語・地域を反映することが求められる。バンドルが提供する翻訳資源の範囲だけには制限しない。

前提: OS が、利用者が端末で選択した現在の言語・地域を取得する公開 API を提供している。

## Decision

ライブラリが自動生成する日付・時刻の表示は、OS が提供するアプリ単位の言語設定があればそれを優先し、なければ端末全体で選択された現在の言語・地域に従う。アプリ独自の言語設定は参照せず、バンドルが提供する localization の範囲だけにも制限しない。対象は Picker の選択面と Cell 右側の自動生成値であり、両者は同じ時点の Locale から導出して表示言語・日付要素の順序・午前午後表記を一致させる。

アプリバンドルが提供すると宣言した localization の範囲だけに表示言語を制限しない。OS の Locale 変更が実行中の Host へ通知された場合は、表示中の Picker と Cell 右側値を同じ Locale へ更新する。再表示・再バインドされる値は変更後の Locale から再計算し、以前の Locale で生成した formatter や文字列を再利用しない。

`TimePickerCell` の 12 / 24 時間制は引き続き `is24Hour` を唯一の決定源とする (core/ADR-0028)。Locale は時制を決定せず、選択された時制における言語・地域表現だけを担う。

## Alternatives Considered

- **アプリが提供する localization の範囲で Locale を解決する**: 却下。プラットフォーム慣用のアプリ言語とは揃うが、日本語の端末でもアプリが日本語資源を宣言していなければ英語へフォールバックし、Android / MAUI iOS の観測結果および「日本なら日本の形式」という利用者期待と一致しない。
- **端末全体の言語だけを使い、OS のアプリ単位言語設定を無視する**: 却下。OS が利用者に提供するアプリ単位の選択は、そのアプリで利用者が明示した表示言語として尊重する。

## Consequences

- 正: Picker の選択面と Cell 右側値が同じ言語・地域になり、同一 Cell 内の表記分裂を防げる。
- 正: Native iOS・Android・MAUI iOS で、利用者が選択した言語・地域に対する日付・時刻表記を揃えられる。
- 負: アプリが端末の言語を localization として提供していない場合、Picker と日付・時刻値だけが周辺 UI と異なる言語になる可能性がある。
- 負: formatter や自動生成文字列のキャッシュは Locale を識別子に含めるか、Locale 変更後に再生成する必要がある。
- 負: 実行中の Locale 変更を受けた Host は、表示中の Cell を再バインドする必要がある。
