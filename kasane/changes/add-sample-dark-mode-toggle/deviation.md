# Deviation: add-sample-dark-mode-toggle

- samples-ios / samples-android / samples-maui の Requirement「外観の切り替え」Scenario「ダークを選ぶとライブラリ既定色の画面が暗く描画される」: spec では THEN「画面はライブラリ既定色のダーク描画になり」 → 指示により 3 面とも「アプリ chrome と Theme 明示画面はダーク描画、Theme を渡さない画面 (isVisible デモ・Section 装飾デモの箱) はライブラリ既定色のまま (背景・Cell 背景・separator は固定ライト値、title / description の文字色だけ外観に追随 = ダークでは白地に淡色文字)」に縮小し、選択中の「ダーク」の識別と外観の反映 (chrome・Theme 明示画面・選択面) を本 change の達成範囲とする。理由: ライブラリ本体の Theme 既定色が 3 面とも外観に追随しない固定値である — iOS は `ios/Sources/KsSettingsViewUI/Theme.swift` の `defaultBackgroundColor` / `cellBackgroundColor` の既定引数 / `defaultSeparatorColor` / `defaultHeaderTextColor` が固定 RGB で、dynamic なのは `defaultCellTitleColor` (`.label`) と `defaultCellDescriptionColor` (`.secondaryLabel`) のみ。Android は `android/kssettingsview/src/main/kotlin/jp/kamusoft/kssettingsview/ui/Theme.kt` の `DEFAULT_BACKGROUND_COLOR` / `cellBackgroundColor` / `DEFAULT_SEPARATOR_COLOR` / `DEFAULT_CELL_DESCRIPTION_COLOR` が固定値で、`ui/EffectiveStyle.kt` の title 既定だけが同梱 DayNight テーマの `textColorPrimary` から解決される。MAUI は native をラップするため同じ。本 change 以前から端末を夜間 / ダークにしても同じ状態であり、proposal の Non-Goals (ライブラリ本体の既定値・夜間モード解決の変更) を守る。本体側の追随は別 change `fix-default-colors-dark-appearance` (cross、exploration.md のみの簡易起票) で扱う。探索時の「iOS のライブラリ既定色はシステム色で自動追随する」(exploration.md) と concepts `kasane/concepts/core/styling/style-resolution.md` の「Android のライト / ダークは ... 端末の夜間モードとアプリの uiMode 制御で決まる」は、Theme の既定色定数には当てはまらない記述として蒸留時に乖離を反映する (2026-09-05、当初 Android 限定で裁定した後、iOS 面の検証で同症状が判明し同日 3 面へ拡張)
- proposal Non-Goals「ライブラリ本体 (Theme の既定値・夜間モード解決) の変更」/ samples-maui Requirement「外観の切り替え」の「ページの下地とライブラリ UI が追随の対象」: spec・proposal では本体に触れない前提 → 指示により、MAUI iOS で「ダーク」選択時に予約日の選択面 (カレンダーシート) の地色がライトのまま描かれる件 (証跡 `ui/verification/maui-ios-calendar-dark-range.png`。「システム」+端末ダークでは正しくダーク、iOS Native では「ダーク」選択でも正しい) を**本 change で iOS 本体側を修正して解消する**。理由: MAUI の `UserAppTheme` による外観上書きがライブラリのシート提示コンテナへ届かず、利用者が MAUI で `UserAppTheme = Dark` を使っても同じ現象になり得るため、サンプル側の回避ではなく本体で直す (オーナー裁定 2026-09-05)。修正範囲は iOS 本体の提示経路 (シート・ポップオーバー等、同型の提示を持つ箇所すべて) に限り、Theme 既定色の追随 (前項) は引き続き `fix-default-colors-dark-appearance` で扱う
- ui/brief.md「承認モック」/ 承認モック `ui/mock/approved.png` (plan-a.html) の基本 Cell 7 種デモ: モックでは「無効なボタン」行が描かれ ButtonCell の文言が「登録」 → 指示により、モックの規範範囲を「配色 (色ロール対応表) とルートメニューの外観 UI (項目群と選択中の表現)」に限定し、行構成・文言の差分 (「無効なボタン」行は 3 面のどこにも無い、ButtonCell は 3 面とも「ログアウト」) は合意済み差分として実装を現行構成のまま維持する。理由: どちらもモック作成時の創作で、spec はこのデモの構成変更を求めていない (sample-parity 上も 3 面は一致している)。モックの構成が現行実装と一致していなかった点は `kasane/lessons/inbox/mock-shows-param-not-matching-current-impl.md` に捕捉済み (オーナー裁定 2026-09-05、second-opinion-code-003 の指摘を受けて)
