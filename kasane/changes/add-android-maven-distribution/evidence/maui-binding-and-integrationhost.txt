# MAUI binding のビルドと Android IntegrationHost の実行確認 (2026-09-01)

統合後の 2 本の aar (`kssettingsview-release.aar` 同梱 / `kssettingsview-bridge-release.aar` 束縛)
から binding をビルドし、実機で固定シナリオの成立を確認した。

## binding のビルド

$ dotnet build maui/android/KsSettingsView.Binding.Android/KsSettingsView.Binding.Android.csproj -c Debug
    20 個の警告
    0 エラー

警告の内訳は BG8605 / BG8606 / BG8A00 (各 2 重出力) のみ。いずれも本変更以前から出ている
既知の警告であり、内容も同じ:

- BG8605 / BG8606: 同梱のみ (Bind="false") の aar 内の型を class-parse が解決できないもの。
  統合前は `core` / `ui` の 2 本が同梱対象、統合後は `kssettingsview` 1 本が同梱対象で、
  未解決として列挙される型 (`jp.kamusoft.kssettingsview.core.KsAnyView` 等) は同じ
- BG8A00: `Transforms/Metadata.xml` の `remove-node` が generator 段では対象なしになる
  2 段適用に由来する恒常警告 (同ファイルのコメントと maui/README.md に記載済み)

## IntegrationHost のビルドと起動

$ dotnet build maui/tests/KsSettingsView.IntegrationHost.Android/KsSettingsView.IntegrationHost.Android.csproj \
    -c Debug -t:Run -p:AdbTarget="-s <android-serial>"
ビルドに成功しました。
    0 個の警告
    0 エラー

$ adb -s <android-serial> shell dumpsys activity activities | grep -i integrationhost
topResumedActivity=ActivityRecord{... jp.kamusoft.kssettingsview.integrationhost.android/....MainActivity}

接続端末は 2 台あるため `AdbTarget` で明示した (実機。Emulator ではない)。

2 枚のスクリーンショットは、端末の通知アイコンを証跡に残さないためステータスバー
(上端 110px) をクロップしてある。照合に使う行はすべてクロップ後の画像に含まれる。
