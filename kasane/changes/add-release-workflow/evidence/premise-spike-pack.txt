2. pack 拡張点の実測 (SDK 側の結線)
================================================================
Microsoft.Android.Sdk.AndroidLibraries.targets の該当箇所:
    <_AarOutputPath>$(OutputPath)$(TargetName).aar</_AarOutputPath>
    <TargetsForTfmSpecificContentInPackage>$(TargetsForTfmSpecificContentInPackage);_IncludeAarInNuGetPackage</...>
    _IncludeAarInNuGetPackage が TfmSpecificPackageFile へ $(_AarOutputPath) を Include する

  => 除外は TfmSpecificPackageFile からの Remove で行える。

================================================================
3. 実行順の実測 (design の記述との差)
================================================================
design / tasks は「TargetsForTfmSpecificContentInPackage の末尾に除外ターゲットを足す」としている。
maui/Directory.Build.targets からこのプロパティへ追記した状態で値を取ると:

$ dotnet msbuild ... -getProperty:TargetsForTfmSpecificContentInPackage
    ";_PackProjectToolValidation;KsCheckGeneratedAarEntries;KsExcludeGeneratedAarFromPackage;_IncludeAarInNuGetPackage"

  => Directory.Build.targets の追記は SDK の追記より前に並ぶ。この並びでは Remove が Include より
     先に走り、pack 結果に aar が残った (実測: 改変後も lib/net10.0-android36.0/KsSettingsView.Maui.aar
     が nupkg に存在)。検査ターゲットも aar 生成前に走るため Exists() が偽で無音になり得る。

     採った形: プロパティへの追記はやめ、両ターゲットを AfterTargets="_IncludeAarInNuGetPackage"
     (検査は除外ターゲットの DependsOnTargets) で結線する。あわせて aar が存在しない場合は
     黙って通さず Error にした。

5. Scenario: 生成 aar に自前の内容が入ると pack が失敗する
================================================================
一時的に生成 aar へ res/values/dummy.xml を追加してから pack した (原状復帰済み)。

$ zip -r <REPO>/maui/KsSettingsView.Maui/bin/Release/net10.0-android/KsSettingsView.Maui.aar res
$ dotnet pack maui/KsSettingsView.Maui/KsSettingsView.Maui.csproj -c Release -o <SCRATCH>/pack-fail

<REPO>/maui/Directory.Build.targets(67,5): error : 自 assembly 用 aar
    (bin/Release/net10.0-android/KsSettingsView.Maui.aar) に推移依存の native ライブラリ以外が
    入っている: res/, res/values/, res/values/dummy.xml。この aar は nupkg から外しているため、
    同梱が必要な内容であれば除外方式を見直すこと。

  => pack は失敗し、想定外のエントリが出力で確認できる。nupkg は生成されなかった
     (<SCRATCH>/pack-fail は作られていない)。

原状復帰: 退避しておいた aar を書き戻し、エントリが jni/*/libandroidx.graphics.path.so の 4 件に
戻ったこと・退避元と byte 一致することを確認した。

リポジトリの作業ツリーには何も残していない。
