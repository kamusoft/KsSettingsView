# scripts/release/ の単体確認 (tasks 5.4)

採取日: 2026-09-03 / 採取環境: macOS (arm64)、bash 3.2 / python3 3.11 / unzip (Info-ZIP)

Android の発行物サンプルは `cd android && ./gradlew publishToMavenLocal -Pversion=0.0.0-spike.1`
(JDK 17、署名鍵なし) の出力を使った。生成されたのは 5 成果物 (aar / pom / module /
sources jar / javadoc jar) で、署名鍵が無いため `.asc` は 1 件も出ない。以下の確認は
その出力を一時ディレクトリ (`<work>`) に複製したものに対して行い、mavenLocal 自体と
リポジトリの作業ツリーは変更していない。ログ中の `<repo>` はリポジトリルート、
`<work>` は一時作業ディレクトリを表す。

`maven-metadata-local.xml` のケースだけは、成果物 5 件に加えて `publishToMavenLocal` が
書き出す `~/.m2/repository/jp/kamusoft/kssettingsview/maven-metadata-local.xml` も含めて
複製し (`<work>/a/jp` と `<work>/b/jp`)、B 側の `<lastUpdated>` だけを別の値に書き換えた
2 本で実行した。このファイルは発行のたびに時刻が変わるため比較対象から外してあり、
成果物 5 件だけを比較して一致と判定する。

## 「公開済みか」を返すエンドポイントの確認 (tasks 1.1 の一部)

Central Portal Publisher API の公式ドキュメント
(https://central.sonatype.org/publish/publish-portal-api/) が定義するのは、bundle の
upload (`POST /api/v1/publisher/upload`)、deployment の状態照会
(`POST /api/v1/publisher/status?id=`)、release (`POST /api/v1/publisher/deployment/<id>`)、
drop (`DELETE /api/v1/publisher/deployment/<id>`)、deployment 内ファイルの download
(`GET /api/v1/publisher/deployment/<id>/download/<path>` と
`GET /api/v1/publisher/deployments/download/<path>`) の 6 つで、**座標 + version が
Maven Central へ公開済みかを返すエンドポイントは無い**。download 系は deployment
または validated な deployment を起点にするため、過去に公開済みかの判定には使えない。

したがって `central-portal.sh published <version>` は Maven Central の配信元
`https://repo1.maven.org/maven2/jp/kamusoft/kssettingsview/<v>/kssettingsview-<v>.pom`
への HEAD で判定する。認証は不要で、200 = 公開済み、404 = 未公開、それ以外は判定不能
(exit 2) として扱う。

## step の終了ステータス (release.yml の run ブロックをそのまま実行)

`check-distribution-tag.sh` を呼ぶ 2 つの step の `run` を PyYAML で release.yml から
取り出し、上と同じ合成リポジトリ (remote に内容の異なる `1.0.0` がある状態) に対して
`bash` で実行した。validate 側は CI 固有の 2 行 (github.com からの clone とスナップショット
生成) だけを合成に差し替え、残りはそのまま実行している。

    step                                 remote の tag の状態          step の exit
    validate: Verify distribution        内容が異なる同名 tag          1
      repository tag
    publish: Push distribution           内容が異なる同名 tag          1
      repository tag
    publish: Push distribution           同名 tag が無い               0 (tag を作成して push)
      repository tag

判定結果を代入で受けているため、スクリプトの exit 1 が `set -e` に載って step が失敗する。
tag 作成の直前でも、失敗理由は git の重複エラーではなく検査のエラー出力になる。

## 保留 deployment の ID をログから拾い直す経路 (モックによる机上確認)

`Publish Android to Central Portal` と `Recover deployment id from upload log` の `run` を
release.yml から取り出し、`central-portal.sh` / `check-signatures.sh` /
`compare-maven-artifacts.sh` / `gradlew` を呼び出しを記録するだけのモックへ差し替えて
実行した (ネットワークにも作業ツリーにも触らない)。両 step は同じ環境変数で upload の
ログの位置を共有する。

    ケース                                        結果
    upload まで通る (公開されていない)             出力 deployment-id=(抽出値) / release-needed=true、
                                                  ID ファイルに同じ値
    ID を出力する前に落ちた (ログだけ残る)         `::warning::` を出して出力 deployment-id=(同じ値)
    upload に入る前に落ちた (ログが無い)           出力なし (ID なしのまま続行)

拾い直した ID は `Summarize` の表と `Drop pending deployment` の条件・入力に載る。

## wait-for-registries.sh の補足確認 (tasks 2.3)

5.4 の対象外だが、ポーリングの骨格だけ手元で確かめた。

- 未公開の version (`0.0.0-never-published`) を与え、`KSR_POLL_INTERVAL_SECONDS=2` /
  `KSR_POLL_TIMEOUT_SECONDS=4` で実行すると、Maven Central と nuget.org の 3 Package ID の
  4 件すべてを未反映として繰り返し報告し、上限で `::error::` を出して exit 1 になった
  (環境変数による間隔・上限の上書きが効いている)。
- nuget.org の index.json の判定 (`versions` に当該 version が含まれるか) を合成データで確認:
  大文字小文字の違う `1.2.3-BETA.4` と `1.2.3-beta.4` はどちらも一致 (exit 0)、
  含まれない `9.9.9` は exit 1、JSON として壊れた応答も exit 1。

公開済みの正ケース (4 件すべてが揃って exit 0 になること) は、対象の 3 Package ID と
Maven 座標がまだどこにも公開されていないため手元では踏めない。初回リリースの本番 run で
初めて通る経路になる。
