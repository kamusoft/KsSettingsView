# Deviation: add-release-workflow

- design.md Decision 10 / tasks 1.2・3.2 (pack 拡張点の結線方法): design では「`TargetsForTfmSpecificContentInPackage` の末尾に生成 aar の除外ターゲットを足す」→ 実測により `AfterTargets="_IncludeAarInNuGetPackage"` (検査ターゲットは除外ターゲットの `DependsOnTargets`) で結線した。理由: `maui/Directory.Build.targets` からのプロパティ追記は Android SDK 側の追記 (`_IncludeAarInNuGetPackage`) より前に並び、Remove が Include より先に走って aar が nupkg に残った (evidence/premise-spike-pack.txt)。依存する非公式識別子が「プロパティへの追記位置」から「SDK の内部ターゲット名」に変わるが、SDK 更新で壊れたら失敗させる検査 (生成 aar が存在しなければ Error) を同居させる点は Decision 10 の受容リスクと同じ。デルタスペック (maui-nuget-distribution) の契約は変わらない (2026-09-03)
- tasks 4.1 (配信リポジトリの同名 tag の比較手段): tasks では「`git diff --quiet` で比較」→ 実装は `git add -A` → `git write-tree` の結果と `refs/tags/<v>^{tree}` のハッシュ比較。理由: スナップショットは未追跡ファイルを含み `git diff` では検出できない。spec「その tag のツリーが起動 commit から生成したスナップショットと異なれば失敗する」の判定内容は同じ (2026-09-03)
- Requirement「Maven Central の 2 段操作」(再実行時の状態分岐): spec は VALIDATED / PUBLISHING / PUBLISHED / FAILED の 4 状態のみを定める → 実装は前回 deployment が PENDING / VALIDATING (検証中) のときは 30 秒間隔・上限 30 分で決着を待ってから 4 分岐に入る (上限で失敗)。理由: 検証中は結論が出ていないだけで、4 状態の意味を変えずに穴を塞ぐ。spec に記述の無い状態の扱いとして記録する (2026-09-03)
- [付随修正] `maui/nuget.config` は実装ワーカーの環境設定 (`NuGet.Config` へのアクセス拒否) で作成できなかったため、オーケストレーターが作成した (tasks 3.1)。作業機は nuget.org と社内フィードの 2 ソース環境 (evidence/premise-spike-pack.txt の 7〜8 節で NU1507 が出ていた環境) で、適用後は `maui/` 配下の解決先が nuget.org のみになり facade の restore で NU1507 が 0 件になることを確認した — Scenario「複数ソース環境でも nuget.org だけから取得する」はこの環境で充足している (2026-09-03)
- tasks 1.3 / 1.4 (実測手段): 実測には一時 workflow `.github/workflows/spike-release-premise.yml` (workflow_dispatch) を用いる。tasks には削除タスクが無いため、ここに記録する: **1.3 / 1.4 の実測完了後にこの一時 workflow を削除する** (review-001 の Suggestion) (2026-09-03)
- Requirement「マージ保護」(`main` への取り込み制限の方式): second-opinion-code-001 の指摘「`pull_request` の lint job 内の検査は、`main` 向け PR 自身が ci.yml を書き換えて無効化できる」に対し、オーナー判断で **現状 (design Decision 6 の CI lint job 検査) のまま受け入れる**。理由: 起動できるのは collaborators のみ (cross/ADR-0024) で、意図的に検査を消す PR は運用上の逸脱として扱う。Ruleset / `pull_request_target` 化は採らない (残存リスクとして記録) (2026-09-03)
- [付随修正] `kasane/config.yaml` の `lint.comment-policy.ext` に `.sh` / `.py` を追加。理由: `scripts/release/` の script も既存の `scripts/spm-snapshot/` `verification/**/*.sh` も comment-policy の機械検査の外にあった (実装ワーカーの発見)。追加後の lint は違反 0 件。オーナー判断で同梱 (2026-09-03)
