# Exploration: docs-refresh-3e-hardening

## 課題 / 動機

skills-api-coverage (2026-08-29) で docs-refresh に新設した 3e (API 名網羅検査、`.agents/skills/docs-refresh/SKILL.md`) の残課題 2 点。review-002 のレビュアー推奨により起票。

1. **en 側の検出漏れ**: 3e は ja 版のみを検査するため、en 側だけ API 名が落ちる「翻訳時の系統的取りこぼし」と同型の穴が en に残る。6-②/③ (見出し・コードブロック検査) は散文を見ないため代替検査もない。en/ja は同一サブエージェントが同時生成する運用なので発生確率は低い
2. **ノイズ削減**: 3e の残トークンは既知ノイズ 3 層 (core concepts のクロスプラットフォーム記述による他プラットフォーム名 / 内部型・プラットフォーム標準型 / 意図的な掲載除外 API) で数百トークン規模。報告のみ + Step 4 承認ゲートの設計なので誤書き換えは起きないが、提示の可読性が低い。実運用データが溜まってから対策 (除外リスト・ソース分類等) を決めるのがよい (先回りフィルタは真の漏れを落とすリスクがある — review-002 の見解)
