# install-examples デルタスペック

## ADDED Requirements

### Requirement: インストール例の version 表記

README と利用者向け Skill のインストール例は、具体的な version を持たない SHALL。version の位置にはプレースホルダを置き、そのプレースホルダは依存解決に成功しない形である SHALL。

- インストール手順には、最新版を確認できる案内を置く SHALL。案内先は、その時点の最新リリースへ解決される位置とする。
- SwiftPM の依存宣言は `exact:` で書く SHALL。`from:` は下限が prerelease であれば prerelease も解決するが、上限が次のメジャーまで開くため特定の版に固定されない。
- 配布物に同梱される README も同じプレースホルダのままとする。
- リリースはインストール例を書き換えない SHALL。書き換えないため、リリースは入力された version とインストール例の一致を検査しない。契約 (プレースホルダであること等) の検査は日常の検証 CI が行う。

#### Scenario: 埋めずに使うと依存解決が失敗する
- **GIVEN** インストール例をそのまま写した消費者プロジェクト
- **WHEN** 依存を解決する
- **THEN** 解決は失敗し、プレースホルダが埋められていないことが分かる

#### Scenario: 最新版の案内から目的の版に着地できる
- **GIVEN** インストール手順を読んでいる利用者
- **WHEN** 手順に置かれた最新版の案内をたどる
- **THEN** 最新のリリースのページに着き、そこに書かれた version を得られる

#### Scenario: リリースしてもインストール例は変わらない
- **GIVEN** 任意の version を入力した release の実行
- **WHEN** release が最後まで成功する
- **THEN** リポジトリのインストール例は変更されておらず、version の一致を理由に中断した箇所も無い

### Requirement: インストール例の契約の検査

インストール例が契約を満たしていることは、日常の検証 CI で機械的に検査される SHALL。検査する内容は次のとおり。

- 対象の各行がプレースホルダを持ち、具体的な version を持たないこと
- SwiftPM の依存宣言が `exact:` で書かれていること
- README と各 Skill に、最新版の案内があること
- 英語版と日本語版が同じ Skill 名の集合を持ち、対応する各 Skill が同じ種類・同じ本数のインストール宣言を持つこと

検査の対象 (ファイルと、その中の宣言の種別と本数) は、検査する側が明示的に持つ SHALL。対象を持たない走査で代替しない。

あわせて、利用者向け Skill の実際の構成と対象の一覧を突き合わせる SHALL。対象に無い Skill が存在する場合、対象にあるのに実在しない場合、英語版と日本語版で数や名前が食い違う場合は、いずれも失敗とする。

#### Scenario: 具体 version への逆戻りを検出する
- **GIVEN** インストール例のいずれかの行に具体的な version が書き戻された状態
- **WHEN** 検証 CI の lint job が実行される
- **THEN** 検査が失敗し、どのファイルのどの行かが分かる

#### Scenario: SwiftPM の宣言が `exact:` でなくなったことを検出する
- **GIVEN** SwiftPM の依存宣言が `from:` に書き換えられた状態
- **WHEN** 検証 CI の lint job が実行される
- **THEN** 検査が失敗する

#### Scenario: 検査対象に登録されていない Skill を検出する
- **GIVEN** 新しい利用者向け Skill が追加され、検査の対象一覧に登録されていない状態
- **WHEN** 検証 CI の lint job が実行される
- **THEN** 検査が失敗し、登録されていない Skill が分かる

#### Scenario: 英日の構成のずれを検出する
- **GIVEN** 片方の言語の Skill にだけインストール例が追加された状態
- **WHEN** 検証 CI の lint job が実行される
- **THEN** 検査が失敗する
