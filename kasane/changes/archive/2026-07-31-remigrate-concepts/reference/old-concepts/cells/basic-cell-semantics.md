## 基本 Cell の役割

基本 Cell は、情報の表示、処理や遷移の要求、明示的な操作、二値の切り替え、チェック状態、グループ内の単一選択という設定行の意味を、プラットフォーム間で対応させる。

各 Cell は表示時点の内容と状態を持つ不変の値モデルである。Native control のライフサイクルや画面全体の状態保持は担わない。

## 値と操作通知

二値、チェック、選択状態は Cell の内容であり、値等価と hash に含める。利用者操作を伝えるコールバックは振る舞いであり、内容ではないため値等価と hash から除外する。

利用者操作はコールバックを通じて外部の状態所有者へ通知する。宣言 UI では状態所有者が新しい状態値を Cell へ写し直し、Store 利用では更新されたモデルを共通更新経路へ渡す。

グループ単一選択では、各項目が自身の候補値と共有された現在値から選択表示を導く。各項目は選択集合を所有せず、現在値の更新と他項目への伝播は外部の状態所有者が担う。

## 似た表示を持つ役割の区別

- Checkbox は独立した二値を、明示的な checkbox control で表す。
- Radio は共有された現在値に対する候補を表し、グループ内で一つだけ選ぶ。
- Simple check は独立した選択状態を、リスト項目の簡易な印で表す。

印の見た目が似ていても、状態所有と選択規則は交換可能ではない。

明示的な操作を表す Button は、移植元との意味互換を維持するため description を公開しない。これは共通内容に対する公開 API 上の例外である。

## 横断状態との境界

無効と非表示は独立する。無効はモデルを残したまま操作と[視覚状態](styling/cell-visual-states.md)を変え、非表示はモデルを残したまま visible projection から外す。

既定生成では各インスタンスに新しい識別子を与えられる。宣言 DSL が再評価をまたぐ[安定同一性](architecture/declarative-tree-identity.md)へ再束縛することと、Store 利用者が識別子を明示することは、基本 Cell の生成責務とは分離する。
