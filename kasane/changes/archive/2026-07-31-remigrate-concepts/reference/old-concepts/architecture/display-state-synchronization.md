## 原則

モデルの値等価と、表示構造を追跡する同一性は別の契約である。値等価はテストや一般的な値比較に使い、構造同一性には識別子だけを使う。

表示状態の同期は次の三経路に分ける。

1. 構造同期: Section / Cellの追加、削除、移動、識別子変更を扱う。
2. 内容更新: 同じ識別子の行を破棄せず、表示内容だけを再構成する。
3. 可視性変化: 非表示要素を含むmodelからvisible projectionを再構築する。

Themeはこの三分類とは独立した画面状態であり、構造変更へ混ぜず専用の更新経路で反映する。

## 不変条件

- 内容を含む値等価を、構造上の同一性判定に使わない。
- 同じ識別子のCellに対する置換は、同一行の内容再構成を意味する。
- 連動する複数Cellの内容変更は、一つの更新世代として同じcommit後に再構成する。
- 識別子が変わる差し替えは構造変更として扱う。
- 可視性は通常の内容更新へ押し込まず、model内の位置と内容を保ったままprojectionを更新する。
- Theme更新を構造・内容・可視性のいずれかへ擬装しない。
- 識別子の一意性はモデル利用者が保証する。

## 用語

- model: 非表示要素を含む設定ツリーの完全な状態。
- visible projection: modelから表示対象だけを射影した派生状態。
- reconfigure: 同じ識別子の行を破棄・再生成せず、表示内容だけを更新すること。
- update generation: 連動する複数の内容変更を、同じ状態commitに属する更新として扱う単位。
