# samples-maui — デルタスペック (restore-maui-picker-selected-command)

## ADDED Requirements

### Requirement: 入力 Cell デモの複数選択を選択完了通知で受ける

MAUI サンプルの入力 Cell デモにある複数選択の「通知先メンバー」行は、選択位置を TwoWay バインドで保持し、直近イベント表示の更新を選択完了通知の受信によって行わなければならない (SHALL)。iOS / Android のサンプルが同じ行を選択完了 callback で実装しているため、この行だけが選択値の変化を観測する経路になっているとプラットフォーム間の経路が揃わない。

この行の表示文言 (section の header / footer、行の title、候補と初期選択、選択面のタイトル) を変更してはならない (SHALL NOT)。文言は 3 platform で一致しており、経路の入れ替えは表示に現れない。

#### Scenario: 選択を確定すると直近イベントが更新される

- **GIVEN** 入力 Cell デモを表示している
- **WHEN** 「通知先メンバー」の選択面で顔ぶれを変えて確定する
- **THEN** 直近イベント表示が確定後の顔ぶれで更新され、iOS / Android の同じ操作と同じ文言になる

#### Scenario: 同じ顔ぶれを再び確定しても直近イベントが更新される

- **GIVEN** 入力 Cell デモで「通知先メンバー」以外の行を操作し、直近イベント表示がその別の行の内容になっている
- **WHEN** 「通知先メンバー」の選択面で選択を変えずに確定する
- **THEN** 直近イベント表示が「通知先メンバー」の内容へ戻る

この Scenario の GIVEN が別の行の操作を挟むのは、直近イベント表示が同じ文言で上書きされると発火の有無を区別できないためである。

#### Scenario: 確定せずに閉じると直近イベントが変わらない

- **GIVEN** 入力 Cell デモを表示している
- **WHEN** 「通知先メンバー」の選択面を確定せずに閉じる
- **THEN** 直近イベント表示は選択面を開く前のまま変わらない

### Requirement: MAUI 固有 Cell 機能デモ画面

MAUI サンプルは、他 platform に対応概念のない facade 固有の Cell 機能を集めた画面を持ち、ルートメニューの「MAUI 固有」区分に置かなければならない (SHALL)。この画面は他 platform への追随義務を負わず、以後の facade 固有機能を同じ画面へ足せる器として扱う。

この画面が主対象とする facade 固有の意味論は次の 2 つである。native は選択完了を関数として渡す形でしか公開しておらず、バインド可能な command として公開する形と、選択要素列そのものを TwoWay で受け取る形はいずれも MAUI facade にしか存在しない。

- 選択完了通知をバインド可能な command として受け取れること
- 選択要素列そのものを TwoWay バインドで受け取れること

画面は単一選択と複数選択の PickerCell を 1 行ずつ持ち、各行について次を観測できなければならない (SHALL):

- その行の選択値 (単一選択は選択項目、複数選択は選択要素列) がバインド先へ反映されていること
- その行が選択完了通知を受け取った回数

回数を示すのは、選択完了通知が「値の変化」ではなく「操作の完了」を表すため、同じ選択を確定し直したときの発火が値の表示だけでは観測できないことによる。

#### Scenario: 画面がルートメニューから開ける

- **GIVEN** サンプルアプリのルートメニューを表示している
- **WHEN** 「MAUI 固有」区分の Cell 機能デモの項目を選ぶ
- **THEN** その画面が開き、画面タイトルはルートメニューの項目文言と一致する

#### Scenario: 単一選択の確定で選択項目と受信回数がともに更新される

- **GIVEN** MAUI 固有 Cell 機能デモを表示している
- **WHEN** 単一選択の行の選択面で候補を変えて確定する
- **THEN** バインド先が保持する選択項目が確定後の候補になり、その行の受信回数が 1 増える

#### Scenario: 複数選択の確定で選択要素列と受信回数がともに更新される

- **GIVEN** MAUI 固有 Cell 機能デモを表示している
- **WHEN** 複数選択の行の選択面で顔ぶれを変えて確定する
- **THEN** バインド先が保持する選択要素列が確定後の顔ぶれになり、その行の受信回数が 1 増える

#### Scenario: 同じ選択の再確定でも受信回数が増える

- **GIVEN** MAUI 固有 Cell 機能デモを表示している
- **WHEN** 単一選択・複数選択のいずれかの行で、選択を変えずに確定する
- **THEN** その行の選択値の表示は変わらず、受信回数だけが 1 増える

#### Scenario: 確定せずに閉じると受信回数が増えない

- **GIVEN** MAUI 固有 Cell 機能デモを表示している
- **WHEN** 単一選択・複数選択のいずれかの行で、選択面を確定せずに閉じる
- **THEN** その行の選択値も受信回数も変わらない
