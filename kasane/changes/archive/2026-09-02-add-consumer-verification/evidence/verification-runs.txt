smoke の参照先は公開レジストリで、準備済みの配布物 (スクリプトの --reference / workflow の
artifact 入力) を差し込む余地がない。黙って無視すると「渡した配布物を検証した」と誤解される
ため、組み合わせ自体を早期に拒む形にした (オーナー判断)。

--- スクリプト (3 platform 共通の引数解釈) -----------------------
$ ./verification/<platform>/build-consumer.sh \
      --mode smoke --version 0.1.0-rc.1 --reference <既存ディレクトリ>          (exit 1)
  エラー: smoke では --reference を指定できません
          (参照先は公開レジストリで、準備済みの配布物は使いません)

  ios / android / maui とも exit 1。prepare-feed.sh に同じ組み合わせを与えた場合も exit 1。
  出力はこのエラー 1 行だけで、引数解釈の最後に出る「platform=... mode=... version=...」の
  行も現れない = フィード準備にも依存解決にも入っていない。

既存の負ケースの回帰 (3 platform とも exit 1 のまま):
  build-consumer.sh --mode nope        -> 1
  build-consumer.sh --mode smoke       -> 1 (version 省略)

--- workflow (入力検査ステップ) ----------------------------------
消費者検証 3 本の Validate inputs (checkout より前、download-artifact より前) に、
mode が smoke かつ artifact が空でない場合を ::error:: つきで落とす分岐を足した。
検査の順序は mode の許可値 -> smoke の version 必須 -> smoke + artifact の禁止。
