# Exploration: restore-adr-decision-records

## 課題 / 動機

`kasane/decisions/` の ADR のいくつかが、決定の記録ではなく**変更ログ**として読める状態になっている。
オーナー指摘 (2026-09-07): 「ADR-0020 の書き方は間違えてる。履歴代わりに使うのは NG」。

### 機械判定の結果 (2026-09-07、ADR 96 本を全件走査)

**accepted 後に本文 (Context〜Revisit When) が変わった ADR は 6 本**。うち 5 本は無害:

| ADR | 変更内容 | 判定 |
|---|---|---|
| cross/0016・0017・0023 | handbook 移送に伴うリンク文字列の張り替え | 無害 (決定内容は不変) |
| maui/0010・0026 | footer の出典行の追加 | 無害 (footer は規約上可変) |
| cross/0018 | Decision 節へ配布座標の更新を 2 件追記 (2026-09-01 / 09-02) | **違反** |

**本題は書き方**: 「(YYYY-MM-DD 追記)」マーカーの累積と、Consequences への非決定記述の流入。
多くは proposed 期に書かれており accepted 後の改変ではないが、結果として ADR が変更ログになっている。

| ADR | 追記された内容 | 本来の層 |
|---|---|---|
| cross/0018 | 配布座標の更新 3 件 (SwiftPM identity・Android 単一 artifact・MAUI 3 パッケージ) | 現況 → concepts |
| cross/0019 | 「tag トリガーは ADR-0020 に置き換わった」1 件 + prerelease 形式の規約 2 件 | 関係 → frontmatter / index、規約 → 決定本文 |
| cross/0020 | Decision 2・Alternatives 4・Consequences 3 + 実装結果ブロック 7 項 | 決定は本文へ、実測値・運用手順は concepts / handbook |
| cross/0021 | 公開対象の範囲の確定 1 件 (Decision) + lint / hook を置いた実装結果 1 件 (Consequences) | 決定は本文へ、実装結果は落とす (現況は `scripts/` と config が正) |
| cross/0023 | README 対象外範囲の確定 1 件 (Decision) | 決定は本文へ |
| cross/0028 | CI 所要時間の実測 (7.7 分の内訳) 1 件 | 実測値 → concepts |
| android/0019 | 「実装で確定した 2 点」(experimental API の範囲・版整合の既定) | 事実 → concepts、既定 → 決定本文 |
| maui/0015 | 「上記 (1) は解消済み」(積み残しの消化状況) | 変更ログ → 落とす |

混入しているのは 3 種類: **(a) 決定そのもの / (b) 実測値・現況 / (c) 課題の消化状況と ADR 間の関係**。
是正の型が種類ごとに違うため、この分類がそのまま作業単位になる。

**対象は 8 本 / 計 22 行**。cross/0021 と cross/0023 は日付付きマーカーを行の途中に埋めていたため節ごとの走査では目立たず、
機械検出 (本文から frontmatter と footer を除き、同一行に日付と「追記」がある行を拾う) で後から判明した。96 本を走査して偽陽性 0 件。

規模: cross/ADR-0020 は Consequences が 3714 字 / 15 箇条で本文の約 6 割を占める。所要 39 分・Trusted Publishing の
初回 login・`--skip-duplicate` の冪等性など「今どうなっているか」を含み、うち deployment ID の運用・
`set-readme-version`・所要 39 分は handbook `cross/release-procedure.md` と**二重管理**になっている。

### 根本原因

ksn-distill Step 3c が「実装を経て判明した帰結があれば Consequences に追記してよい (出典: 実装結果)」を
明示的に許しており、プロジェクトはこれに従った結果こうなった。**ハーネス側の見直しは本変更の対象外**
(オーナー裁定 2026-09-07)。プロジェクト側の是正と再発防止だけを扱う。

## 検討した選択肢 (却下案と理由を含む)

### 論点 1: accepted ADR の本文を、是正のために書き換えてよいか

| 判断軸 | A: 本文を是正 (採用) | B: 本文据え置き・移送のみ | C: supersede で書き直す | D: 触らない |
|---|---|---|---|---|
| 二重管理の解消 | 解消する | 残る | 解消する | 残る |
| 決定記録の完全性 | 保たれる (決定部分は不変、旧本文は git) | 保たれる | 保たれる | 保たれる |
| 規約との整合 | 「本文不変」の明文には触れる (趣旨では外と読む) | 完全に整合 | 完全に整合 | 完全に整合 |
| 読み手の誤読リスク | 低 (footer に整理の記録) | 中 (変更ログのまま残る) | 高 (superseded 8 本 = 決定が覆ったと読める) | 中 |
| 作業量 | ADR 8 本 + 移送先 2 本 | 移送先のみ | 新 ADR 8 本 + 旧 8 本の status 更新 | なし |

- **A を採用** (2026-09-07)。「本文不変」は決定の改訂を禁じる規定であり、決定内容を変えない層違反の是正は趣旨の外と読む。旧本文は git に残る
- **B は却下**。現に起きている二重管理をそのまま固定し、層の原則 (情報は 1 つの層にだけ属する) を満たさない
- **C は却下**。決定は何も覆っていないのに `superseded` が 8 本増え、index の読み手に「決定が変わった」と誤読させる。status の意味が壊れる
- **D は却下**。変更ログ化した 8 本と二重管理が残り、ADR を読んだ人が現況として古い実測値を受け取る状態が続く

### 論点 2: 実装結果の移送先

ADR-0020 の実装結果ブロック 12 要素のうち **8 件は既に concepts / handbook にあり削除で足りる**。さらに 2 件も不要:
`--skip-duplicate` の冪等性は handbook `cross/release-procedure.md` の「公開済みのパッケージは skip される」が同じことを言い、
Trusted Publishing の初回 login は一度きりの観測で初回リリース済みの今は価値がない。**移送先が要るのは 3 件**:

| 移送する内容 | 残す理由 |
|---|---|
| Portal の 2 段階操作の機構と制約 (plugin に保留 deployment を release するタスクが無く、Portal に一覧 API も公開確認 API も無いため、ID のログ抽出と API 直接呼び出しが唯一の手段) | 外部 API の**不在**は再導出コストが高く、ID をログから抜く理由がこれ |
| 公開確認は `repo1.maven.org` への HEAD で代替する | 上と同じ制約から来ており、切り離すと理由が読めなくなる |
| publish job が鍵つきで再ビルドしたものを upload する (dry-run の未署名成果物ではない。署名ファイルを除く同一性比較で差異があれば upload しない) | dry-run の成果物をそのまま出さない理由 |

| 判断軸 | A: 新概念 `cross/architecture/release-pipeline.md` (採用) | B: repository-boundaries.md へ追記 | C: handbook release-procedure.md へ |
|---|---|---|---|
| 層の判定 | 文書を直す側 = concepts で正しい | 同じく正しい | 誤り (外部 API の制約や実装構造を規範層に置くと違反検査の対象になる) |
| 主題の一貫性 | リリース機構で閉じる | 責務境界の主題が薄まる | 手順書に機構の説明が混ざる |
| 分割トリガー | 新規なので余裕 | 9256 字 → 10000 字超 | 該当なし |

- **A を採用** (2026-09-07)。あわせて既存のリリース記述 (配信リポジトリの commit / tag の分離、publish 段の構成) も新ファイルへ寄せる
- B は却下 (主題が薄まり分割トリガーを超える)、C は却下 (層の判定が誤り)

### 論点 3: cross/ADR-0018 の座標追記の扱い

決め手は ADR-0018 自身の Decision 末尾の宣言 —「Android の artifact 粒度と MAUI のパッケージ分割は本 ADR の対象外とし、
それぞれ別の決定で扱う」。2026-09-01 / 09-02 の追記は、この ADR が自分で対象外と書いた領域の結果を後から書き戻したもので、
**決定の改訂ではなく現況の反映**だった。amends は決定を一部置き換える型なので、覆っていない以上使えない。

移送も不要。現況の座標は `concepts/cross/architecture/repository-boundaries.md` の build root の表が 3 platform 分すべて持つ
(Android の単一 artifact `jp.kamusoft:kssettingsview`、MAUI の NuGet 3 パッケージを含む)。

削除後に Decision の座標表が決定時点の `jp.kamusoft:ks-settingsview-*` のまま残る点への対策:

| 案 | 内容 | 評価 |
|---|---|---|
| (i) 何もしない | ADR は決定時点の記録という性格上、当然のこととして扱う | 誤読が読み手の注意頼みになる |
| (ii) footer に現行照合を書く (採用) | `現行照合: <日付> 確認。表の座標は決定時点のもので、現況は concepts の build root の表が持つ (…)。判定: 維持` | ksn-core の正式な仕組み。本文は不変のまま在り処を示せる |
| (iii) Decision 表に「(決定時点)」と注を入れる | 読み手の目に直接入る | 本文の改変になる |

判定は「維持」— 決定した内容 (公開レジストリの標準チャネルのみ) は今も生きており、変わったのは ADR が対象外と宣言した粒度のほう。

### 論点 4: 再発防止

| 案 | 評価 |
|---|---|
| A: プロジェクトに lint を置き日付付き追記マーカーを禁じる | 却下。試作では 96 本から 22 行を偽陽性 0 で検出でき実効性はあるが、ハーネス本体側で対応する方針のため二重になる |
| B: プロジェクト handbook に「ADR の書き方」規約を置く | 却下。ksn-core `references/decisions.md` が既に「提出前セルフチェック: 決定の記録か、変更ログに堕ちていないか」と「本文不変」を持ち、同じ規約に対する正が 2 つになる |

## 決定事項

- accepted ADR の本文は**層違反の是正に限り**書き換える。決定内容 (Context / Decision / Alternatives Considered) は不変 (2026-09-07)
- 日付マーカー「(YYYY-MM-DD 追記)」は本文から落とし、決定が 1 つの文章として読める形に溶かす
- 是正した ADR の footer に `整理: <日付> <何をどこへ移したか>。決定内容は不変` を 1 行足す (footer は規約上可変)
- supersede / amends は使わない (決定が覆っていないため)
- **この是正を ADR に残さない** (2026-09-07、オーナー却下)。理由は次の 2 つ
  - ハーネス (ksn-core) が定める「accepted 本文は不変」への例外を利用側プロジェクトの `decisions/` で作るのは層の踏み外し。ハーネスの規律を変える決定は Kasane リポジトリが持つ
  - 是正・保守は決定ではないので ADR の対象外。ADR の掃除を ADR に書くのは、本変更が直そうとしている変更ログ化そのもの
- 是正を許す根拠はオーナーの指示であり、記録は本探索メモで足りる。ksn-core の「本文不変」が守っているのは**決定の記録の不変性**であり、実測値・消化状況を正しい層へ戻す保守はその対象外 (例外を開ける必要自体がない)
- 実装結果の移送先は新概念 `kasane/concepts/cross/architecture/release-pipeline.md`。既存のリリース記述も `repository-boundaries.md` から寄せる (2026-09-07)。この配置は選別 3 基準のいずれにも当たらないため ADR は起こさない
- cross/ADR-0018 の座標追記 2 件は Decision から削除する。amends / supersede は使わない (決定が覆っていないため)。移送も不要 (現況は concepts が既に持つ) (2026-09-07)
- **8 本共通の是正の型** (2026-09-07): 本文から現況・実測値・消化状況を落とし、在り処を footer の `現行照合` 1 行で示す。日付マーカーは本文から落として決定が 1 つの文章として読める形に溶かす
- 再発防止はプロジェクト側では lessons のみ。lint / 規約はハーネス本体側で対応する (2026-09-07)

## 変更級の推奨: S (2026-09-07 オーナー確定)

コード変更なし・公開 API 変更なし・UI なし・git で可逆。規模 (長命層 10 ファイル) はあるが、何をどう直すかは本探索で
確定済みで proposal は探索メモの写しにしかならない。品質ゲートは新規概念の初見可読性レビュー + 構造 lint +
S 級必須の独立レビューで揃う。前例は `changes/archive/2026-09-05-restructure-maui-api-concepts` (concepts 大規模再編を
同じ理由で S 級確定)。

| 材料 | 本変更 |
|---|---|
| 触る対象 | ADR 8 本 (本文の是正 + footer の現行照合) / 新規 `concepts/cross/architecture/release-pipeline.md` / 既存 `concepts/cross/architecture/repository-boundaries.md` (移送元) = 計 10 ファイル |
| コード変更 | なし |
| 公開 API | 変更なし |
| UI | なし |
| 可逆性 | 可逆 (git) |

前例との違いは `decisions/` の本文に触れる点だが、可否は論点 1 で、是正の型は論点 3 で確定済みのため実行時の判断余地は小さい。

## 実行

**ksn-concept** (既存 concepts / decisions の手入れモード) が担う。前例と同じ経路で、構造 lint と初見可読性レビューの
ゲートもそちらが持つ。S 級のため独立レビューは必須。

作業単位は「混入の 3 種類」で割れる:

1. **決定そのもの** (cross/0019 の prerelease 形式、cross/0020 の tag 表記・main 起動と却下案 4 件、cross/0021 の公開対象範囲、cross/0023 の README 対象外範囲、android/0019 の版整合の既定) — 日付マーカーを落として本文へ溶かす
2. **実測値・現況** (cross/0018 の座標 2 件、cross/0020 の実装結果 12 要素、cross/0028 の CI 所要、android/0019 の experimental API 範囲) — 8 件は既存記述と重複のため削除、3 件を `release-pipeline.md` へ移送、Trusted Publishing の初回 login は価値を失っており削除
3. **消化状況・ADR 間の関係** (maui/0015 の「解消済み」、cross/0019 の「ADR-0020 に置き換わった」、cross/0021 の lint / hook 設置) — 落とす。関係は frontmatter と index が持つ

全 8 本に共通して footer へ `現行照合: <日付> 確認。<在り処と要点>。判定: 維持` を 1 行足す。
