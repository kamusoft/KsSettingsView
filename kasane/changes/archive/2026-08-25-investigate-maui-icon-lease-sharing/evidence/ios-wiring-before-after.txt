# 2.2 配線確認: iOS 共有防御の before/after 実測 (2026-08-25)

注意: これは tasks 1.1 の probe (iOS 26.0.1 / maui/spike) とは別ランタイム・別ハーネスでの計測。
この環境でも共有が実際に起きていたことは、baseline 列 (配線なしで片方の除去だけで handle が 0x0
になる) が同一環境で示している。

環境: iPhone 17 Pro / iOS 26.5 Simulator。maui/tests/KsSettingsView.MauiHost を一時改造
(asset catalog 画像 probe_icon + 同一 IconSource の 2 Cell + 段階的除去ボタン。計測後に撤去済み)。
観測点: probe 側で UIImage.FromBundle("probe_icon") して保持した UIImage の Handle
(facade が解決するのと同一インスタンスであることは tasks 1.1 の probe で実証済み)。

| 操作 | 配線あり (実装後) | 配線なし (baseline) |
|---|---|---|
| 初期 (2 Cell が共有) | handle = 0x10395A940 | 同左 |
| 片方の Cell を外す | handle = 0x10395A940 (維持) | handle = 0x0 (破壊された) |
| 残りの Cell も外す | handle = 0x0 (後片付けが走る) | — |

- 配線あり: 片方の除去では画像が生存し、最後のリース破棄で後片付けが実行される (解放漏れなし)
- baseline では片方の除去で UIImage が破壊されるが、残った行の icon は画面上は描画されたまま
  (UIImageView 側の native retain のため)。画面の見た目だけでは検出できない欠陥であり、
  handle の直接観測を採った理由

# 所有権分類 (D 案) への設計変更後の再実測 (2026-08-25)

環境: iPhone 17 Pro / iOS 26.5 Simulator。maui/tests/KsSettingsView.MauiHost を同じ形で一時改造
(asset catalog 画像 probe_icon + 同一 IconSource の 2 Cell + 段階的除去/置き直しボタン。計測後に撤去済み)。
観測点は上と同じ — probe 側で UIImage.FromBundle("probe_icon") して保持した UIImage の Handle。

| 操作 | 分類あり (D 案) | 参照カウント版 (旧設計) | 分類も防御も無し (baseline) |
|---|---|---|---|
| 初期 (2 Cell が共有)   | handle = 0x104172D00 | 0x10395A940 | 同左 |
| 片方の Cell を外す     | 0x104172D00 (維持)   | 0x10395A940 (維持) | 0x0 (破壊された) |
| 残りの Cell も外す     | 0x104172D00 (維持)   | 0x0 (後片付けが走る) | — |
| 外した後に置き直す     | 0x104172D00 (維持・icon は正しく描画) | — | — |

- 新しい期待値どおり、最後の Cell を外した後も画像は破壊されない。この画像を所有しているのは
  UIKit の名前付き画像キャッシュであり、facade は後片付けの口を付けないため誰も破棄しない
- 旧設計 (参照カウント) との差は最終行。旧設計は最後のリースで managed peer を破棄していたが、
  それは native の実体を解放しない (キャッシュが retain を保持) 一方で、キャッシュが同じ名前に
  返し続ける managed peer を無効化する操作だった
- 置き直しで同じ handle のまま icon が描画されることまで確認した。破棄していないため、
  キャッシュが返す実体はそのまま使える状態で残っている
- 本計測が押さえるのはキャッシュ所有の分岐。facade 所有 (実ファイルから起こした画像) の分岐は
  解決結果の口をそのままリースへ渡す従来どおりの経路で、分類の単体テストと
  controller レベルのテストが受け持つ (probe 側からは facade が解決した実体を掴めないため)

# 所有権分類の asset 種別ごとの実測 (2026-08-25)

環境: iPhone 17 Pro / iOS 26.5 Simulator。maui/tests/KsSettingsView.MauiHost を一時改造
(4 種別の icon を持つ Cell + 一括除去ボタン)。iOS の解決口へ一時的に計測ログを仕込み、
「分類結果」と「後片付けが実際に走ったか / 走った結果 handle が 0 になったか」を直接観測した。
計測後、ログも足場もすべて撤去済み。

## 修正後 (照合キー = ディレクトリと拡張子を落とした名前)

| # | 指定 | asset 種別 | 分類 | 後片付け口 | 全 Cell 除去時 |
|---|---|---|---|---|---|
| 1 | probe_asset      | asset catalog / 拡張子なし | cache 所有  | 付けない | 実行されない (画像は無傷) |
| 2 | probe_asset.png  | asset catalog / 拡張子付き | cache 所有  | 付けない | 実行されない (画像は無傷) |
| 3 | probe_bundle.png | bundle 直下 png (MauiAsset) | facade 所有 | 付ける   | 実行され handle 0x...DA0 -> 0x0 |
| 4 | probe_maui.png   | MauiImage 生成 png          | facade 所有 | 付ける   | 実行され handle 0x...E40 -> 0x0 |

- #1 と #2 は **handle が同一 (0x104166D00)**。拡張子の有無で書き分けても UIKit の名前付き画像
  キャッシュは同じ実体を返す — 共有が実在することの直接の証跡
- #3 #4 は互いにも #1 #2 とも別の handle で、除去時に確かに破棄された (解放漏れなし)。
  Requirement「非共有画像は従来どおり直ちに後片付けされる」に実測が付く

## 照合キーを生のファイル名に戻したミューテーション (修正前の欠陥)

| # | 指定 | 分類 | 後片付け口 | 全 Cell 除去時 |
|---|---|---|---|---|
| 1 | probe_asset      | cache 所有  | 付けない | 実行されない |
| 2 | probe_asset.png  | **facade 所有 (誤分類)** | **付ける** | **実行され handle 0x1035683C0 -> 0x0** |
| 3 | probe_bundle.png | facade 所有 | 付ける | 実行され 0x0 |
| 4 | probe_maui.png   | facade 所有 | 付ける | 実行され 0x0 |

#2 の handle 0x1035683C0 は #1 が表示に使っているものと同一。生の名前で引くと asset catalog の
資産名 (拡張子なし) と一致せず、共有されている画像に後片付け口が付き、その破棄が #1 の表示を
壊す。誤分類が表示破壊に直結することを実物で確認した。修正後 (上の表) ではこの経路が消えている。
