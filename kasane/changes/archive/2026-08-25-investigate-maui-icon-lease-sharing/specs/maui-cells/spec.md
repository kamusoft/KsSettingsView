# Delta Spec: maui-cells (investigate-maui-icon-lease-sharing)

> 前提: 本デルタスペックは tasks 1.x の probe で iOS の画像インスタンス共有が再現した場合にのみ有効になる。非再現の場合はこの ADDED Requirement を撤回し、probe-only の調査として change を閉じる (撤回の記録要件は tasks 1.2)。

## ADDED Requirements

### Requirement: 共有 platform 画像の後片付け安全性

icon の解決が同一の platform 画像インスタンスを複数の解決結果として返した場合、いずれかの解決結果の破棄によって、まだ表示に使われている他の解決結果の icon 表示を壊してはならない (SHALL NOT)。この保護は解決口 (resolver) の世代交代 (Host 再接続) をまたいでも、異なる SettingsView の間でも働かなければならない (SHALL)。

画像の実際の後片付けについては次を満たさなければならない (SHALL):

- 同一画像を包むリースが残っている間、後片付けは一切実行されない (0 回)
- 最後のリースが破棄された時点で、その画像について保持されていた全ての後片付け口が各 1 回だけ実行され、以後その画像に関する保持は残らない (解放漏れ・エントリ残留をしない)
- 各リースの破棄は冪等であり、同一リースの多重破棄が後片付けの多重実行やカウントの不整合 (underflow) を起こさない
- 共有されていない画像の後片付けは、そのリースの破棄時に従来どおり直ちに実行される

また、同一の Cell が再解決の完了時に表示中と同一の画像インスタンスを受け取った場合、表示内容は変わらないため native への差し替え配信は行わず、旧リースはその場で解放されなければならない (SHALL)。

#### Scenario: 同一 Cell の再解決で新旧リースが同一画像を包む

- **GIVEN** icon 表示中の Cell の再解決 (Host 再接続時の一括再解決) が、表示中と同一の platform 画像インスタンスを返した
- **WHEN** 新しい解決結果が控えられ、旧リースがその場で解放される
- **THEN** 画像の後片付けは実行されず、Cell の icon 表示は維持される

#### Scenario: 解決口の世代交代をまたいだ共有

- **GIVEN** 旧 Host 世代の解決口が返した画像を表示中の Cell がある
- **WHEN** 再接続後の新しい解決口が同一の画像インスタンスを返し、旧リースが解放される
- **THEN** 画像の後片付けは実行されず、icon 表示は維持される

#### Scenario: 2 つの Cell が同一画像を包む

- **GIVEN** 2 つの Cell の icon が同一の platform 画像インスタンスに解決されている
- **WHEN** 片方の Cell を登録解除し、その除去の配信後にリースの破棄が走る
- **THEN** 画像の後片付けは実行されず、残る Cell の icon 表示は維持される

#### Scenario: 控えられない解決結果の即時破棄でも共有画像は守られる

- **GIVEN** icon 表示中の Cell がある
- **WHEN** 控えられない解決結果 (追い抜かれた解決・旧世代の解決・登録解除済み Cell への解決) が表示中と同一の画像インスタンスを包んで到着し、その場で破棄される
- **THEN** 画像の後片付けは実行されず、icon 表示は維持される

#### Scenario: 最後のリースの破棄で後片付けが実行される

- **GIVEN** 同一の platform 画像インスタンスを包むリースが複数あり、最後の 1 つ以外は破棄済み (この間、後片付けは 0 回)
- **WHEN** 最後のリースが破棄される
- **THEN** その画像について保持されていた全ての後片付け口が各 1 回だけ実行され、以後その画像に関する保持は残らない

#### Scenario: 非共有画像は従来どおり直ちに後片付けされる

- **GIVEN** 他のリースと画像を共有しないリース
- **WHEN** そのリースが破棄される
- **THEN** 画像の後片付けが直ちに実行される (後片付けが参照カウントの解放を担う環境で解放遅延を生まない)
