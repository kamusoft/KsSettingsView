- [設計の変更] Android の受け口を、Host の具象型ではなくモジュール内部の `RootAccessoryReceiver` として切り出し、知らせに配送元の Store を載せた。Host は現在結び付いている Store と一致する更新だけを受理する。理由: design.md は受け口の形として具象型を指定していないが、配送元の識別が無いと、ある Store の配送の途中で別 Store への bind / unbind が挟まったときに以前の Store の値を受理してしまう (2026-09-17)
- [設計の変更] MAUI の設定ツリー全体の事前実体化 (`MaterializeTreeViews`) は、後片付け待ちの実体を持つ View を対象から外す。この分は従来どおり配信の後に実体化して送る。理由: 表示中の Root の作り直しでは同じ View が残るため、事前実体化が native の参照する旧 wrapper を配信前に破棄することになり、maui/ADR-0016 の退役順序に反する (2026-09-17)
- [設計の変更] MAUI の `KsSettingsController.Disconnect` で、View の実体化の口と画像の解決口も手放す。理由: 実体化の口の差し込みが接続より前へ移った結果、初回接続が例外で終わったときに口だけが残り、gateway が無いまま作った実体が次の接続へ持ち越される窓ができた (2026-09-17)
- [付随修正] `maui/KsSettingsView.Maui.Tests/Fakes/GatewayScope.cs` の空になった `Attach()` と、その呼び出し 39 箇所 (`AccessoryViewTests.cs` / `CustomCellContentTests.cs` / `CustomCellTests.cs` / `ImplicitStyleTests.cs` / `LeakTests.cs` / `LogicalChildTests.cs` / `ThemeAndCellStyleTests.cs`) を取り除いた。理由: 何も起きない操作が「取り付けを再現している」ように読め、取り付けの検証は Handler の実経路のテストに集約されている (2026-09-17)
- [設計の変更] Android の受け口は `KsSettingsView` 自身に実装させず、Host が private に持つ受け口オブジェクトへ移し、そこから Host の private メンバへ委譲する。Store は受け口オブジェクトを弱参照で、Host は受け口オブジェクトを強参照で持つ。理由: Kotlin の `internal interface` のメンバは JVM で名前修飾されないため、public クラスが直接実装すると配送用のメソッドが公開 API として露出し、design.md の「モジュール内部の口」「公開 API の変更は無い」に反する (2026-09-17)
- [設計の変更] MAUI の `KsSettingsController.Disconnect` の実体の後片付けは、登録済みの Section / Cell をたどる形ではなく、置き場所の対応表 (`_accessories` / `_cellContents`) を直接走査する形にする。あわせて `SettingsView.ConnectGateway` は gateway を作ってから実体化の口を差し込む。理由: 設定ツリーの実体化は対応表への登録より前に進み、gateway を作る呼び出しは接続の後始末の外側にあるため、どちらも失敗した世代の実体と口を次の接続へ持ち越す窓になる (2026-09-17)
- [設計の変更] Android の Store の配送失敗の握り潰しから、コルーチンのキャンセルの合図を除外して投げ直す。理由: 公開 API から呼ばれる更新の中で協調的キャンセルが起きたとき、構造化並行性の合図が消える (2026-09-17)
