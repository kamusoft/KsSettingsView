## 指摘事項

### [🟠 Major] 未照会の対象が「未反映」として出力される

**該当箇所**: `scripts/release/wait-for-registries.sh:315`、`scripts/release/wait-for-registries.sh:339`、`scripts/release/wait-for-registries.sh:355`

**問題点**: 全対象を最初から `STATE_PENDING` で初期化しています。1巡目の途中で期限に達すると、残りの対象は一度も照会されないままループを抜けますが、出力では「未反映」になります。

デルタスペックは「照会できたうえで当該versionがない状態」を未反映と定義しています。未照会は、照会結果としての未反映でも、通信失敗・HTTP異常・解釈失敗でもありません。したがって現在の出力は「照会できた」と「照会していない」を区別できず、変更の中心契約に反します。

既定45分では最初の1巡が最大8分なので通常は表面化しませんが、サポートされている `KSR_POLL_TIMEOUT_SECONDS` の短縮時には実際に到達します。

**推奨修正**: 各対象に「照会済みか」を保持する配列、または `STATE_UNCHECKED` を導入してください。期限によって照会できなかった対象は「未照会（期限到達）」などと出力し、`has_unreflected` では未完了として扱います。1巡目の途中で期限へ達し、一部だけが照会済みになるケースも自己テストへ追加してください。

### [🔵 Suggestion] 45＋2＜60の関係を機械検査する

**該当箇所**: `.github/workflows/release.yml:916`、`scripts/release/wait-for-registries.sh:95`、`scripts/release/wait-for-registries.sh:378`

**問題点**: 現在値での算出は正しいです。対象ごとの開始前判定があるため、期限を越えられるのは開始済みの照会1件だけで、スクリプト上界は概ね45分＋120秒＝47分です。intervalを増やしてもsleep前に早期終了するため、上界は広がりません。

ただし、待機上限またはHTTP応答上限を延ばすと60分との関係は破れ得ます。現在はコメントによる手動確認だけで、以前と同じ定数ドリフトをCIが検出しません。また47分はスクリプト部分だけで、job全体にはcheckout時間も含まれます。

**推奨修正**: publishの240分検査とは分けて、レジストリ待機の既定上限、HTTP応答上限、job timeout、および明示したsetup余裕を突き合わせる検査を追加すると安全です。intervalは現在のsleep前判定では上界計算へ加える必要はありません。
