## 5.3 Scenario の同等確認

tasks 5.3 の代替経路「保護設定の検査で同等確認」を採用した。admin バイパスを許容する
設定であるため、admin アカウントで直 push や未通過マージを実試行しても拒否されず、
Scenario の確認にならないため。

実際の PR に保護が効いていることの確認:

```
gh pr view 1 --json mergeStateStatus,mergeable,statusCheckRollup
```

```json
{"checks":[{"conclusion":"SUCCESS","name":"ios / verify"},{"conclusion":"SUCCESS","name":"android / verify"},{"conclusion":"SUCCESS","name":"maui / verify"},{"conclusion":"SUCCESS","name":"lint"}],"isDraft":true,"mergeStateStatus":"CLEAN","mergeable":"MERGEABLE"}
```

- Scenario「検査未通過のマージ拒否」: 4 job が required_status_checks に登録され、
  PR のマージ判定に反映されている。4 job すべて SUCCESS のため mergeStateStatus は CLEAN。
  いずれかが失敗していれば BLOCKED となりマージがブロックされる
- Scenario「直 push の拒否」: required_pull_request_reviews の設定により pull_request 経由が
  必須となる (admin バイパスを除く)
