# Evidence: ios-cell-highlight-delayed-on-touchdown

実機での確認はオーナーが行った。確認機は iPhone 11 (iOS 18.7.8) と iPhone 15 (iOS 26.6.1) の 2 台で、
iOS Sample アプリ (`samples/ios/KsSettingsViewSample.xcodeproj`) を Debug 構成で配備して操作した。
Simulator (iPhone 17 / iOS 26.5) にも同じビルドを配備し、調整の各段階で先に確認した。

## 確認した操作と結果

| 操作 | 結果 |
|---|---|
| 「基本 Cell 7 種デモ」の Cell を速くタップする | 指を置いた直後に押下色が出る (長押しを要しない) |
| SwitchCell のスイッチをタップする / スイッチの上から縦にドラッグする | スイッチは即座に反応する。スイッチの上から始めたドラッグはスイッチ操作が優先され、リストはスクロールしない (オーナー判断で許容) |
| リストのスクロールを始める | スクロール開始のタッチでは押下色が出ない |
| CommandCell から次の画面へ push 遷移する (SwiftUI ホスト: NavigationStack の path 更新による push) | 遷移のあいだ押下色が残る。UIKit 直接ホスト (同期 push) は実機未確認で、自動テストで担保 |
| 遷移先から戻るボタンで戻る | 戻りのアニメーションの途中から押下色がフェードアウトする |
| 遷移先からエッジスワイプで戻る / 途中で取り消す | 戻り切ったときに解除され、取り消して留まったときは押下色が残る |
| RadioCell の TypeA / TypeB、CheckboxCell を速くタップする | 選択が切り替わる Cell でも押下色が出てフェードアウトする |
| EntryCell の文字を長押しで選択し、選択ハンドルをドラッグして範囲を広げる (review-001 A-3) | 選択範囲が広がり、リストのスクロールに横取りされない |

push 遷移の確認には、Sample の CommandCell に遷移先を一時的に足して使い、確認後に撤去した
(`deviation.md` に記録)。

## 自動テスト

`ios/Tests/` の全件を Simulator 実行で確認した (1062 tests / 0 failures)。押下色のタイミングは
実機の体感が正であり、テストは次の 7 点を担保する (秒数そのものは固定しない)。

- collection view がタッチ遅延を持たないこと
- スライド操作のコントロール (Switch / Slider とその子孫) の上でタッチを横取りしないこと
- 押下色の表示中に render が平常色で上書きしないこと
- 立ち上がりの待ちの間にキャンセルされたら押下色が出ないこと
- 再利用で押下色の予約・表示状態が持ち越されないこと
- タップ後の選択解除が、遷移が始まったかどうかで分かれること
- タップハンドラ内で同期的に push が始まる UIKit 直接ホストでも遷移の合図が消えず選択が残ること (review-003)
