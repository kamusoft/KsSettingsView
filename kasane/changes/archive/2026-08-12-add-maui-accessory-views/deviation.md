# Deviation: add-maui-accessory-views

- design.md Open Questions (iOS の高さ再計算経路): tasks 1.1 の実測で「wrapper の invalidation 中継だけでは UICollectionView self-sizing の行高さ再計算に届かない」と確定 (対象限定の `invalidateLayout(with: context)` の発行が必要。Android は `requestLayout()` のみで追従)。オーナー裁定により**案A** — native に再計算口を追加 (iOS Controller の対象限定無効化口 + Store の一過性通知 API + Android の `requestLayout` による対称化 + Bridge への同名 API) — を本 change のスコープに含める。proposal Non-Goals の例外条項 (パリティ整備) の発動であり、native の `KsAnyView` 利用者の同一ギャップも同時に閉じる。(2026-08-11)
- design.md Decision 2/5 (差し替え時の旧 view 剥がし): tasks 1.2 の実測で、Android は closure の返却前 detach で閉じる (対策なしだと `IllegalStateException` を実証) が、iOS は旧 view の `superview` が退役セルに残存し closure detach では解けないと確定。**Decision 5 の旧 wrapper 破棄手順に「native 配信後に platform view を superview から外す」ステップを追加**して吸収する (退役順序 Store 更新 → native 配信 → 旧 wrapper 破棄は不変、native 無変更)。この扱いを ADR-0016 / ADR-0017 のどちらへ反映するかは蒸留時に確認する。(2026-08-11)
- design.md Decision 1・5 (論理所有の寿命): design/tasks は `AddLogicalChild` / `RemoveLogicalChild` を wrapper 生成・破棄の一部と規定していたが、レビュー指摘 (second-opinion-code-001 Major 2 — spec の無条件 SHALL「論理ツリー接続 + BindingContext 継承」が Handler 未接続中に破れる) の修正として、**論理所有 (AddLogicalChild + 継承 BindingContext) を BindableProperty の寿命、platform lease を Host の寿命として分離**した。Handler 未接続中 (XAML 構築時・Host 解放中) も継承と変更伝播を維持するため。退役順序 (Store 更新 → native 配信 → 旧実体破棄) は platform lease 側で不変。(2026-08-12)
- 多重配置検出の spec 委譲範囲 (未接続 Section の fallback 経路): spec は多重配置の契約を「既存の Section / CellBase 検出と同一」に委譲しており、CellBase 同型なら「未接続 Section への既配置 View 設定が例外なく論理親を奪う」挙動も許容範囲だったが、オーナー裁定により**既配置 View は fallback で所有を確定しない** (newView.Parent が null または当該 Section 自身のときのみ確定) ガードを追加し、既存配置を壊さない側へ倒した。奪取の代わりに、Section が SettingsView へ登録される時点で controller の多重配置検査が例外を投げ、既存配置は無傷で残る。(2026-08-12)
