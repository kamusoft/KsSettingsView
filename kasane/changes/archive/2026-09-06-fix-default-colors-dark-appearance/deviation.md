# Deviation: fix-default-colors-dark-appearance

実装フェーズでデルタスペック / design と異なる形にしたもの。spec 本体は書き換えない (足場凍結)。

- **未指定色の外観解決 (settings-view-android-ui) / 解決済み Theme が埋めるフィールド**: spec では「`Unspecified` のうち既定セットが値を持つもの (Cell title・Cell description を含む列挙) を埋めた解決済み Theme を全消費者が使う」→ 指示により **Cell title / Cell description は解決済み Theme では埋めず (`Unspecified` のまま)、実効 style の解決 (`EffectiveStyle`) が外観 (`darkTheme: Boolean`) を受けて最終段で light / dark セットの title / description 値へ落とす**。理由: 同 Requirement の「ButtonCell の title 既定は 4 段解決 (ButtonCell → CellStyle → Theme の title → 既定) の最終段で外観から選ぶ」と両立しないため (3 段目が常に値を持つと最終段へ到達せず、ライトでも ButtonCell が青→黒に変わる回帰と iOS との不一致が生じる)。利用者可視の挙動 (夜間の title / description が dark 値、valueText → title のフォールバック、ButtonCell の既定が accent と独立) はすべての Scenario どおりで変わらない。verify では「解決済み Theme の `cellTitleColor` / `cellDescriptionColor` が `Unspecified` のまま」を合意済みの差分として扱う (2026-09-05、オーナー裁定: 案 B)
- **design Decision 5 / `Theme.DEFAULT_*` の色定数**: design では「internal 化する」→ **削除** した。理由: 生値は internal パレット (用途名ロール) に移り、internal 定数を残すと同じ値の出所が 2 つになる。spec の規範 (「公開しない SHALL NOT」) は満たす。icon の 2 定数は据え置き (2026-09-05)
- **internal `EffectiveStyle.from` の `context` 引数**: `resolveDefaultTitleColor` (同梱テーマの `textColorPrimary` 解決) の削除で唯一の用途が消えたため引数を落とし、代わりに外観 (`darkTheme: Boolean`) を受ける。内部 API のみ (2026-09-05)
- **internal placeholder 解決の戻り値**: `Color?` → `Color` (`Color.Unspecified` = platform 既定) に揃えた。`CellStyle.placeholderColor` が非 nullable になったため sentinel を 1 流儀にする。Cell 個別の色フィールド (`EntryCell.placeholderColor` 等) は tasks 1.1 / 1.2 の対象外のため `Color?` のまま (2026-09-05)
- **既定色の外観追随 (settings-view-ios-ui) / ButtonCell の title 既定**: spec では「dark セットの生値は 3 platform で同じ値」で ButtonCell 行も含む → **iOS は `.systemBlue` (システム色) を維持**。design Decision 3 と承認モックの対応表の注記「(Android のみ。iOS は .systemBlue)」に従う。`.systemBlue` の sRGB 換算値 (light ≈ (0, 0.533, 1.0) / dark ≈ (0, 0.569, 1.0)) は対応表の #007AFF / #0A84FF と色空間差で厳密一致しないため、iOS テストは「システム色そのもの・light / dark で異なる値に解決される」ことを検証し、値一致は Android 側のみ。verify では ButtonCell 行の 3 面同値を Android / MAUI(Android) の範囲として扱う (2026-09-05)
- **既定色の外観追随 (settings-view-ios-ui) / light 列の表記**: 承認モックの light 列 hex は現行 float 値の丸め表記 (例 separator 0.78/0.78/0.80 → #C7C7CC、対応表は #C8C7CC)。spec「ライトの既定は本 change 前と同じ値」を優先し、iOS の light テストは本 change 前の literal と厳密比較、dark は対応表 hex と厳密一致。挙動の乖離ではなく検証基準の明確化 (2026-09-05)
- **ライブラリ既定色の light / dark セット (settings-view-android-ui) / factory の列挙**: spec では `lightTheme()` / `darkTheme()` の列挙に Cell title・Cell description を含む (Scenario「dark セットは承認モックの対応表と同値」で title も比較) → 指示により **factory も Cell title / Cell description を埋めない (`Unspecified` のまま)**。裁定 B の原理「title / description は Theme で埋めず描画時の最終段で外観解決する」を公開 factory と Compose DSL 入口の既定値式 (`KsSettingsViewDefaults.theme()`) まで一貫させる。理由: factory が title を埋めると、DSL 入口の既定値式と `darkTheme()` を明示的に渡す利用者の両方で ButtonCell の 4 段解決が 3 段目で止まり、ButtonCell title が白 / 黒になる (視覚照合 8.2 で発見。ライトでは本 change 前の青からの後退)。title / description の外観既定値そのものは internal パレットが持ち、実効 style の最終段で選ばれるため、Scenario「Theme を渡さず夜間モードで表示する」「Compose 入口の既定 Theme は外観で選ばれる」の描画結果は変わらない。verify では factory の `cellTitleColor` / `cellDescriptionColor` が `Unspecified` であることを合意済みの差分として扱う (2026-09-05、オーナー裁定: 案 B')
- **未指定色の外観解決 (settings-view-android-ui) / Scenario「ライトの既定は本 change 前と同じ」**: spec では「Cell title の色も本 change 前の実効値と一致する」→ 指示により **Android ライトの Cell title (と title へフォールバックする valueText) の既定は #000000 (承認モックの light 列) を採用し、本 change 前の実効値 #1D1B20 (同梱 Material3 テーマの `textColorPrimary`) とは一致しない**。design Risks の「同梱テーマの `textColorPrimary` と 2 セットの値は実質同じ」は実測なしの推定で、実際は #1D1B20 ≠ #000000 だった (8.4 のライト A/B で Android Native 5 面・MAUI Android 3 面の title / valueText 差分として発見)。理由: 承認モック light 列 (#000000) と iOS `.label` に揃え、handbook cross/sample-parity.md の「本体既定値の platform 差」を増やさない。Material3 の onSurface (#1D1B20) をライブラリ既定に固定するのは android/ADR-0020 (視覚隔離) の趣旨に合わない。**利用者可視の変化**: 既存利用者の Android ライトで title / valueText がわずかに濃くなる (proposal Impact「ライト外観は変わらない」の例外として蒸留時に concepts へ反映する)。description (#6D6D72) は元から定数で変化なし (2026-09-05、オーナー裁定)

## 付随修正 (同梱条件を満たしその場で直したもの)

- [付随修正] Android `SectionBoxMetrics` の `sectionBorderColor ?: 既定` が非 null 化で無効化し `Unspecified.toArgb()` (透明黒) に落ちていたのを `takeOrElse` に修正 (tasks 1.5 の実体) (2026-09-05)

- [付随修正] Android の旧契約を語る doc コメント / テスト名の掃き取り (`DatePickerCellViewHolder` / `PickerDialogColors` / `RadioCell` の「→ プラットフォーム既定」→「→ 外観の既定」、`CellStyleTest` / `ThemeTest` / `ThemeRenameTest` の「既定 null」→「未指定」、`BasicCellsTest` の ButtonCell 既定テストをライブラリ既定色そのものの検証に強化、`InputCellsTest` の EntryCell 入力文字色を「同梱テーマの文字色」→「ライブラリ既定」に書き換え — spec「title の既定はホストや同梱テーマの属性から動的に解決しない」どおりの変化) (2026-09-05)
