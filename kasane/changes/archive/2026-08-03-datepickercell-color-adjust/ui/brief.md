# UI Brief: datepickercell-color-adjust

## 画面と状態

対象は Android DatePickerCell (カレンダーモード、`uiStyle = Material`) の日付選択ダイアログ (MaterialDatePicker) のみ。設定リスト本体の見た目は変えない。

- **カレンダー表示モード** (既定起動モード)
  - 状態: 日グリッド表示 (選択日サークル・今日の枠) / 年選択グリッド表示 (年月表示のドロップダウンから遷移)
- **テキスト入力モード** (ヘッダの鉛筆アイコンで切替)
  - 状態: 入力欄フォーカス中 (強調枠とキャレット)
- **共通**: ヘッダ (タイトル + 選択日テキスト + モード切替アイコン)、キャンセル / OK

## リファレンス注釈

- `references/current-calendar-dialog-broken.webp` — **修正前**の実機スクショ (2026-08-02 ユーザー提供)。2 つの不具合の現状記録:
  - ヘッダのタイトル「予約日を選択」と選択日「2026年6月1日」の**重なり** — 今回修正する対象
  - 配色のテーマ非追従 (OK/キャンセルのピンクはホスト Activity テーマ由来の偶発色、選択日の紫は Material 既定) — 今回変更する対象
  - カレンダーグリッドの構造・操作体系は Material 標準のまま**採用** (変更しない)
- 目標状態は mock/ が正

## デザイントークン参照

色はすべて Theme / CellStyle / Cell の解決値を使う (生値を持ち込まない):

- 背景 ← `Theme.backgroundColor` (timepickercell-color-adjust のモック承認で確定済みの方針を踏襲)
- 強調 ← `DatePickerCell.accentColor` → `CellStyle.accentColor` → `Theme.cellAccentColor` の解決値
- 文字 ← `cellTitleColor` の解決値
- アクセント上の文字 ← アクセント色を背景へ合成した実効面とのコントラストによる白/黒自動選択 (`TimePickerColors.onAccent` の導出規則)

解決規則は kasane/concepts/core/styling/style-resolution.md を正とする。導出色 (アクセント上文字等) の導出規則は `TimePickerColors` / `ColorRoles` を再利用する。

## ヘッダ重なりの補正方針

タイトルと選択日テキストの重なり (references 参照) を走査フックで補正する (android/ADR-0008)。補正の見せ方は 2 案をモックで比較:

- **A 案**: 選択日テキストをやや縮小し、Material 標準のヘッダ高さのまま両方を収める
- **B 案**: 選択日テキストのサイズは維持し、ヘッダを縦に広げてタイトルと選択日を再配分する

採用案はモック承認で決定する。補正の実装パラメータは実装タスク冒頭のスパイク (重なり原因の実機確定) で決める。

### 実装で確定した部位の扱い (2026-08-02)

- **ヘッダ下の区切り線**: material 1.12.0 のダイアログ表示では常に非表示。着色対象の実体が無いため適用しない
- **テキスト入力モードの helper**: 日付入力欄に helper は設定されず、モックの `yyyy/mm/dd` は実際には placeholder。placeholder の減光色として適用済み (日付入力済みのときは表示されない)
- **無効日 (min/max 範囲外)** と **年選択の「今年が未選択」**: サンプルアプリでは再現条件が無く実機スクショに現れない。Robolectric テストで担保
- **ホストが Material Calendar のスタイルを上書きした場合**: 通常日にも塗り・枠を持たせた構成では、その日が選択 / 今日と同じロールで描かれる。ライブラリが役割ごとのスタイルを公開しないための限界で、配色がテーマへ寄る方向の誤りに留まる (詳細は `../impl-notes.md`)

## 承認モック

mock/variant-a-compact-selection-text.html を採用 (approved.png、2026-08-02 オーナー承認。同日、セカンドオピニオン Major 5 対応で年選択グリッドのペインを追加し再承認済み — 選択年 = 強調のピル + アクセント上文字、今年未選択時 = 強調の枠、他の年 = 通常文字)。

- ヘッダ重なりの解消は **A 案 (選択日テキストを縮小し、Material 標準のヘッダ高さのまま収める)** で確定。ヘッダのコンテナ高さには手を入れない
- B 案 (選択日サイズ維持・ヘッダ拡張) は不採用 — コンテナ高さの実行時変更が加わるぶん介入が深くなるため
- 配色 (背景 = Theme.backgroundColor、強調 / 通常文字 / アクセント上文字のロール割当) もモックのとおり承認
- モックの CSS 変数の hex は SampleTheme.maui の解決値の仮当て。実装はデルタスペックのトークン解決を正とする (timepickercell-color-adjust で確立した扱い)

## 実装中に確定したデザイン判断 (2026-08-02)

- **ヘッダ重なりの真因**: 実機スパイクにより「CJK グリフが大きいから食い込む」という当初仮説は**棄却**。
  真因は縦位置指定そのものが失われていることで、補正はライブラリが本来意図した縦位置を復元する方式に変更した
  (ADR-0008 の「棄却された場合は補正手段を見直す」に該当。走査フックで補正する方式は維持)。
  実測値と機序は `../impl-notes.md`
- **A 案の見せ方**: 選択日テキストを既定より一段小さくし、ヘッダ高さは Material 標準のまま据え置く。
  幅に収まらない長い日付表記は、読める下限まで追加で縮める (省略記号で切らない)。具体の比率は `../impl-notes.md`
- **減光の派生色**: 無効日 / 無効状態の OK / 非フォーカス時の入力欄枠 / helper・placeholder はいずれも
  「通常文字ロールまたは強調ロールを背景へ薄く重ねた色」として導出する。減光率はモック確定値で、値は `../impl-notes.md`

## 照合結果

`verification/` の 7 枚 (01 カレンダー / 02 日付再選択後 / 03 月移動後 (今日の枠) / 04 年選択グリッド /
05 テキスト入力 / 06 テキスト入力の不正値 / 07 横向き) を `mock/approved.png` と部位対応表で照合
(2026-08-02、実装者)。
色ロールの割当はすべて一致。構造上の差分は以下 1 点で、いずれも A 案の決定に沿った結果:

- **ヘッダ内の縦配置**: モックはタイトルと選択日が近接して見えるが、実装は Material 標準ヘッダの
  既定ベースラインを復元するため両者の間に余白が入る。「標準のヘッダ高さのまま収める」という
  A 案の決定に沿った結果であり、要素の並び順・ロール割当・強調の優先順位はモックどおり

横向き (07) は material がヘッダを左カラムへ回す構成のため、選択日テキストが 2 行に折り返す。
重なり・クリップは無く Requirement の保証構成 (縦・横) を満たす。モックは縦のみのため対応する比較対象は無い。
