# Deviation: release-host-without-bridge-dispose

- Requirement「Host の単独解放」「Native Host の生成と接続」: root の header / footer は Host 再生成に引き継がれない。spec の THEN は「Store 現在状態」の復元であり、root H/F は Store に含まれない Host 単位のプロパティのため文言上の違反ではない (verify-001 は VALID) が、E2E で「解放前に表示していた root H/F が再生成後に消える」ことが判明した (evidence/*-02-after-recreate.png)。理由: 両 OS の SettingsRootStore は root accessory を状態に保存せず Diff 発行のみ行う既存設計で、root H/F を保持しない利用者は Bridge だけだった。オーナー裁定 (2026-08-08) により**現状を仕様として確定** — root H/F は「所有者が値を保持し、Host 生成のたびに再適用する」Native 既存イディオム (SwiftUI DSL の `.rootHeader` と同形) に揃え、Bridge 公開 API doc (makeHost* / releaseHost / updateAccessory) に明記した。phase-2 の facade 実装 (SettingsView コントロール + SettingsViewHandler) が HeaderText / FooterText を自分の状態として保持し、再接続後に updateAccessory で再適用する責務を持つ。注意: Android の再適用は Host を view 階層へ取り付けた後に行うこと — attach 前は Store 購読が張られておらず (`findViewTreeLifecycleOwner()` が null)、`makeHostView` → `updateAccessory` → `addView` の順では再適用が黙って失われる。MAUI の property mapper は `CreatePlatformView` 直後・view tree 追加前に走り得るため、mapper で素直に再適用すると Android だけこの穴を踏む (転記先 2026-08-08 蒸留で確定: phase-2-maui-core agenda の決定事項「Host 取り付け順序」追記 + 新規申し送り「root H/F 再適用の実装注意」、および concepts `maui/api/native-bridge.md` lifecycle 節)
