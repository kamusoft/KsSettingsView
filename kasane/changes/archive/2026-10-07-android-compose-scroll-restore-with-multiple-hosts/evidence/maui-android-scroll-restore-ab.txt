端末での確かめ: MAUI Android で SettingsView のページが重なる構成のスクロール位置 (修正前後の A/B)

環境: Android Emulator (API 36、1080x2400)、samples/maui の Debug ビルド (net10.0-android)
ビルド: before = 既定 id の View Host を window の階層全体 (rootView) で数える判定に一時的に戻したライブラリ / after = 保存の入れ物の範囲で数える判定のライブラリ。サンプル側のコードは両方とも同じ (ナビゲーションバーに「次のデモへ進む」を足したもの)
配備: ビルドを替えるたびに Sample・facade・Android binding の bin / obj を捨ててフルビルドし、-t:Run でエミュレータへ配備した
取り込みの確認: 各ビルドで、生成された aar (kssettingsview-release.aar) と配備した apk の dex の両方から KsSettingsView.hasAmbiguousLibraryDefaultId の呼び出し先を読んだ
  before: aar も apk も getRootView を呼ぶ
  after:  aar も apk も saveContainerRoot を呼ぶ
一時的な戻しの後始末: ライブラリのソースは確かめの後で after の内容へ書き戻し、戻す前に取った SHA-256 と一致することを確かめた。最後にもう一度 after でフルビルドして配備し、apk が saveContainerRoot を呼ぶことを確かめた

経路: ルートメニュー (CollectionView。SettingsView ではない) → スクロール制御デモ (SettingsView) → バーの「次のデモへ進む」→ Header / Footer への View 配置デモ (SettingsView) → 戻る
手順 (各ビルドで同じ。アプリを止めて起動し直してから始める。夜間モードは切った状態から):
  場面 A: ルートメニュー → スクロール制御デモ →「Section へ」→「次のデモへ進む」→ 戻る (戻る動きは録画した)
  場面 B: 場面 A の続きで「次のデモへ進む」→ 上のページを下へ送る → 夜間モードを入れる (Activity が作り直される) → 戻る → 夜間モードを切る (もう一度作り直される)
  遷移の途中: 進む操作と戻る操作のそれぞれについて、操作を出してから約 2 秒の間に画面の階層を 90 回読んだ
観測の読み方:
  title / top-rows: 画面の要素一覧から読んだ、バーの文字と、内容の上から 4 つの文字の要素と上端の座標 (px)。下のページで「Section 4@279」が上端にあれば位置が保たれている
  階層の中の KsSettingsView: Activity の View の階層の一覧に出た View Host の数と id
  ページの Fragment: MAUI がページごとに持つ Fragment の状態。mState=7 は表示中、mState=1 は View を持たない状態。「View の保存状態」は Fragment が控えている View の保存状態に View Host の分があるか

結果:
  観測点 (上にページを積んだとき、下のページの Fragment の View が階層に残るか): 残らない。before / after とも、落ち着いた状態では下のページの Fragment は View を持たず (mState=1)、階層の一覧にある View Host は上のページの 1 つだけ。遷移の途中に 90 回読んだ中でも、View Host が 2 つ並んだ時点は 1 度も無く、1 つのまま別の View へ入れ替わった。録画では戻る動きの間 2 つのページが重なって描かれている (クロスフェード) が、階層の一覧に出るのは常に 1 つだった
  (1) 進んで戻った後の位置: before 保たれる / after 保たれる (進む前も戻った後も Section 4@279)
  (2) View の保存状態からの戻しと Bridge の戻しの食い違い: before / after とも無し
      - 戻った後の位置は進む前と同じで、別の位置にならない
      - 戻る動きの連続フレーム (maui-android-back-frames-<before|after>.png。録画の全フレームを左上から右へ並べたもの) で、下のページは現れ始めから Section 4 が上端にあり、途中で位置が動くフレームが無い
      - 操作の間にアプリの異常終了は無く、logcat に AndroidRuntime の E 行・FATAL EXCEPTION・未処理例外の行は無い。アプリのプロセスは最後まで生きていた
  (3) ページが重なった状態で Activity を作り直した後の位置: before 保たれる / after 保たれる
      - 上のページ: 作り直す前と後で上から 4 つの要素と座標が同じ
      - 戻った後の下のページ: Section 4@279 のまま。夜間モードを切ってもう一度作り直した後も同じ
      - 作り直した後は、どの Fragment も View の保存状態を持たない (MAUI は Activity の作り直しで Fragment を引き継がない)。この場面で位置を戻しているのは Bridge の側だけ
  before と after の差: この経路では観測に差が無い。下のページの View の保存状態は before でも after でも位置を持っていた (ヒープの読み取り)。MAUI は下のページの View を階層から外してから上のページを載せるため、before の数え方 (階層全体) でも View Host は 1 つと数えられ、修正前から View の保存状態に位置が載っていた。修正で新しく保存されるようになる経路ではなかった
確かめていない点:
  - 夜間モードの切り替え以外の作り直し (画面の回転)。このサンプルの Activity は回転を自分で受け取る設定で、回転では作り直されない
  - 遷移の途中の一瞬 (読み取りの間隔は 25〜130ms) に View Host が 2 つ並ぶ時点があるかどうかは、この読み方では否定しきれない
  - タブやモーダルなど、NavigationPage の Push / Pop 以外でページが重なる構成
