## 指摘事項

### [🟡 Minor] 「注釈にせず標準エラーへ出す」検査が、注釈にしていないことを見ていない

**該当箇所**: `scripts/release/central-portal.sh:534-535`

**問題点**: 検査は理由行が `HTTP 503` を含むことだけを見ており、`::error::` を含まないことは見ていない。理由行に注釈の接頭辞を付け直す変異 (E15) は**緑のまま通る**。review-002 の Minor (吸収して成功した実行に赤い注釈が並ぶ) は実装では直っているが、**検査が守っていない**ため黙って戻せる。3 周で潰してきた「検査が名前どおりのことを見ていない」型の最後の 1 つで、しかも今回この検査と一緒に足された挙動が対象になっている。

**推奨修正**: 同じ理由行を 1 度だけ取って、含むことと含まないことの両方を見る。下の形で実測したところ、無変異では緑 (OK 78 件 / NG 0 件)、E15 と同じ変異では `照会できない理由は注釈にせず標準エラーへ出す (::error::deployment の状態を照会できない (HTTP 503): abc)` で NG になった。

```bash
    local unresolved_reason
    unresolved_reason="$(arrange '503 '; deployment_state abc 2>&1 >/dev/null)"
    check "$([ "$(contains "${unresolved_reason}" "HTTP 503")" = "0" ] \
        && [ "$(contains "${unresolved_reason}" "::error::")" = "1" ] && echo 0 || echo 1)" \
        "照会できない理由は注釈にせず標準エラーへ出す" "${unresolved_reason}"
```

**この change で閉じるべきか**: **閉じるべき**。別 change へ送ると、完了条件「緑 0 件」を満たさないままアーカイブすることになり、この change が 3 周かけて立てた規律 (検査は名前どおりのことを見ているか) を、その change 自身の成果物で破ることになる。修正は検査 2 行で、実装には触れない。
