# Deviation: implement-modern-style

- Modern の Section 箱描画 [ios] / margin の実現手段: design.md Decision 2 では「sectionProvider で `section.contentInsets` に margin を反映」としていた → 実測で `NSCollectionLayoutSection.contentInsets` の上下成分は boundary supplementary の内側 (Header と Cell 群の間) に入り、spec Scenario「top 余白は Header の上・Header と箱の間には入らない」と矛盾するため、複合方式 (水平 = `section.contentInsets` + supplementary の `contentInsets`、Section 間の上下 = `interSectionSpacing`、list 端の上下 = `UICollectionView.contentInset`) に変更。理由: spec (挙動の正) を満たすため。spec の全 Scenario は充足 (2026-08-20)
- Root Header / Footer と `sectionMargin` の関係 [cross]: spec 沈黙領域。初期実装は list 端の上下余白を Root Header の上 / Root Footer の下 (箱群の外側) に置いたが、オーナー判断により**内側**へ変更 — Root Header → 余白 → 先頭 Section / 末尾 Section → 余白 → Root Footer の順とする。Root H/F が無い場合は従来どおり list 端に余白。両 OS とも同配置 (2026-08-20 オーナー決定)
- Modern の Section Header / Footer 行への水平 inset [android]: spec の箱描画 Requirement「Section Header / Footer 行は…水平方向の inset 対象にもしない (SHALL NOT)」は、同 spec 冒頭の共有契約「sectionMargin は Section 単位 (Header・Cell 箱・Footer 一体) の外側余白」および iOS spec の Scenario と矛盾していた。オーナー指示によりこの SHALL NOT を上書きし、H/F 行にも `sectionMargin` の水平成分を適用して iOS と揃える (箱が H/F を覆わない点は変更なし)。理由: 共有契約と承認モックの意図に一致させる (2026-08-20 オーナー決定)
- ボーダーの描画タイミング [android]: design.md Decision 4 は「背景とボーダーは onDraw (Cell の下)」→ spec の合成契約「ボーダーは Cell 背景・押下背景より前面 (SHALL)」を満たすため、ボーダーのみ onDrawOver の最後で描画 (Cell は RippleDrawable で行全面を不透明に塗るため onDraw のボーダーは必ず隠れる)。塗りは design どおり onDraw (2026-08-20)
- 角丸 clip の実現手段 [android]: spec 沈黙領域 (観察結果のみ規定)。ItemDecoration に Cell の実 clip 手段がないため、onDrawOver で角丸パスを clipOutPath し箱の外接矩形を `Theme.backgroundColor` で塗る被覆方式を採用。観察結果 (角丸外に Cell 背景が出ない・余白に backgroundColor が見える) は spec と一致。SettingsView の下地に非均一描画を置く将来要件が出た場合は再検討 (2026-08-20)
- 「ボーダー最前面」の実現手段 [ios]: design.md Decision 7 の観察契約は維持しつつ、decoration の zIndex が実行時に効かない (スパイク実測: layer.zPosition 常に 0) ため、Cell 背景・押下背景を箱の内側形状 (ボーダー幅の内側・角丸) へ CAShapeLayer mask で clip する方式で実現。塗りとボーダーは単一 decoration view の CALayer で描画。観察結果 (全周ボーダー可視・角丸外の非描画) は画素テストで検証済み (2026-08-20)
