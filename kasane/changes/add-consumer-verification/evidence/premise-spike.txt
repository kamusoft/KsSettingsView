================================================================
フィード準備:

      -c Release -p:Version=0.0.0-dev -o <SCRATCH>/spike-maui/feed

$ dotnet pack maui/KsSettingsView.Maui/KsSettingsView.Maui.csproj ... (同上)
  => feed に 3 nupkg (+ 3 snupkg) が生成された。

  留意: リポジトリ内での pack 実行時に NU1507 が出る。
    warning NU1507: ... 2 個のパッケージ ソースが定義されています ... : nuget.org, kamusoft
  これは作業環境のユーザー設定 nuget.config が持つソース構成に由来する (本 pack は
  中央パッケージ管理を使うため警告対象になる)。後述の消費者側 restore では
  packageSourceMapping を持つ nuget.config を -p:RestoreConfigFile= で選ぶため NU1507 は出ない。

消費者 nuget.config (dry-run):
  <packageSources>
    <clear />
    <add key="nuget.org" value="https://api.nuget.org/v3/index.json" />
    <add key="ks-local" value="<SCRATCH>/spike-maui/feed" />
  </packageSources>
  <packageSourceMapping>
    <packageSource key="ks-local"><package pattern="KsSettingsView.*" /></packageSource>
    <packageSource key="nuget.org"><package pattern="*" /></packageSource>
  </packageSourceMapping>

正ケース (version 0.0.0-dev、空の RestorePackagesPath):
$ dotnet restore app.csproj -p:RestoreConfigFile=<...>/nuget.dryrun.config \
      -p:RestorePackagesPath=<SCRATCH>/spike-maui/pkgs
  ... app.csproj を復元しました (10.41 秒)。
  => NU1507 は出ない。警告は MA002 のみ
     (「<UseMaui>true</UseMaui> だけでは Microsoft.Maui.Controls の PackageReference は
       自動追加されない」。消費者 csproj に明示 PackageReference を置けば消える。
       dotnet new maui のテンプレートは元から明示している)。

取得元 (パッケージ単位の .nupkg.metadata):
  <SCRATCH>/spike-maui/pkgs/kssettingsview.maui/0.0.0-dev/.nupkg.metadata
    { "version": 2, "contentHash": "...", "source": "<SCRATCH>/spike-maui/feed" }
  <SCRATCH>/spike-maui/pkgs/kssettingsview.binding.ios/0.0.0-dev/.nupkg.metadata
    { ... "source": "<SCRATCH>/spike-maui/feed" }
  <SCRATCH>/spike-maui/pkgs/kssettingsview.binding.android/0.0.0-dev/.nupkg.metadata

  => 3 件ともローカルフィードから取得された。

解決版 (project.assets.json の targets):
  net10.0-android  KsSettingsView.Maui/0.0.0-dev, KsSettingsView.Binding.Android/0.0.0-dev
  net10.0-ios      KsSettingsView.Maui/0.0.0-dev, KsSettingsView.Binding.iOS/0.0.0-dev
  => facade と binding 2 件の版が一致。3.2 の検査はこの 2 ファイルから組める。

負ケース (フィードに無く、ユーザーキャッシュ <HOME>/.nuget/packages に同 version がある):
  作業環境の <HOME>/.nuget/packages には kssettingsview.maui/0.0.1-poc が存在する。
  これを狙って version 0.0.1-poc を要求した。

  (a) 空の RestorePackagesPath あり:
$ dotnet restore app.csproj -p:KsSettingsViewVersion=0.0.1-poc \
      -p:RestoreConfigFile=<...>/nuget.dryrun.config -p:RestorePackagesPath=<SCRATCH>/spike-maui/pkgs-neg
  error NU1102: バージョン (>= 0.0.1-poc) のパッケージ KsSettingsView.Maui が見つかりません
  error NU1102:   - 1 バージョンが ks-local に見つかりました。 [ 最も近いバージョン: 0.0.0-dev ]
  error NU1102:   - <DOTNET_ROOT>/library-packs からのバージョンは考慮されませんでした。
  error NU1102:   - nuget.org からのバージョンは考慮されませんでした。
  => 失敗する。ユーザーキャッシュにも nuget.org にもフォールバックしない。
     (tasks 1.2 の記述は NU1101 を想定していたが、実測は NU1102。フィードに当該 package の
      別 version があるため「version が見つからない」側のコードになる。挙動は spec の
      Scenario「ローカル参照先に無ければ公開済みの版でも失敗する」を満たす。)

  (b) 対照: RestorePackagesPath を与えず既定の global packages folder を使った同じ restore:
$ dotnet restore app.csproj -p:KsSettingsViewVersion=0.0.1-poc -p:RestoreConfigFile=<...>/nuget.dryrun.config
  ... app.csproj を復元しました (656 ミリ秒)。
  => 成功してしまう。ローカルフィードに 0.0.1-poc が無いにもかかわらず、
     ユーザーキャッシュの展開済みパッケージが使われる。
     Decision 2 (実行ごとに空の RestorePackagesPath を使う) が必須であることの直接の実測。
