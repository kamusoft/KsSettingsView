# Deviation: add-consumer-verification

- [付随修正] `android/build.gradle.kts`: 全モジュールの version をカタログ値で無条件に上書きしていた箇所を、`-Pversion=` の注入があればそれを優先しカタログの開発用既定値は注入が無いときだけ使うよう改めた。理由: cross/ADR-0020「CI が Gradle (`-Pversion=`) へ注入する」の Gradle 側の受け口が未実装で、Scenario「version を与えると全 platform に同じ文字列が流れる」(tasks 3.1 / 5.3) が Android で成立しなかった。別能力のファイルのためオーナー判断を仰ぎ「本 change で直す」と決定 (2026-09-02)
- [付随修正] `android/kssettingsview/build.gradle.kts`: 署名の必須/任意を署名鍵 (`signingInMemoryKey` プロパティ) の有無に連動させ、鍵が無い発行は SNAPSHOT 以外の version でも Sign タスクを skip して未署名で通るようにした。あわせて「鍵が未設定のローカル発行は未署名のまま成功する」というコメントを実挙動に合わせて訂正し、SNAPSHOT で Central 向けタスクを実行したときのエラー案内 (カタログの version を変更する旨) を「リリース版の version は `-Pversion=` で注入する」に改めた (1 件目の version 注入の追随。second-opinion-code-001 の Minor を採用)。理由: `signAllPublications()` が SNAPSHOT 以外で署名を必須にしており、署名鍵を持たない dry-run (Requirement「dry-run の参照先」の「書き込み権限・認証情報を持たない」経路) に release version を渡すとフィード準備が失敗し、Scenario「version を与えると全 platform に同じ文字列が流れる」が Android で成立しなかった。release 本番で鍵が漏れていても Maven Central Portal が未署名を拒否するため静かには通らない。別能力のファイルのためオーナー判断を仰ぎ「鍵が無ければ署名を skip」と決定 (2026-09-02)。補足: 「release version × 鍵なし」の経路は本 change の CI (dry-run は version 未指定 = SNAPSHOT) では踏まれず自動担保が無い。phase-8 の release workflow が publish 前 dry-run に release version を渡した時点で CI が通る経路になる (agenda の申し送りに記載)
- Requirement「消費者検証 workflow の再利用契約」/「フィード準備と消費者ビルドの分離」: spec は artifact (外部で準備した配布物) を与えた呼び出しと smoke (公開レジストリからの解決) の組み合わせを定義していない → 指示により `smoke` と artifact (スクリプトでは `--reference`) の同時指定は入力検査で早期に拒否する。理由: 消費者ビルドは smoke で参照先を使わないため、同時指定を許すと artifact を検証したように見えて公開済みパッケージを検証する偽陽性になる (second-opinion-code-001 の Major)。artifact は dry-run 専用 (publish 前検証) とし、publish 後の smoke は version だけを受ける (2026-09-02)
- [付随修正] `kasane/config.yaml`: `lint.identity.allow` に `repo.local` を追加。理由: レビュー証跡 (second-opinion-code-001.md) に含まれる Maven のシステムプロパティ名 `maven.repo.local` を identity-lint が mDNS ホスト名として誤検出し exit 1 になるため。ホスト名ではないことをコメントで注記 (2026-09-02)
