## 指摘事項

### 🟠 Major 論点1 = A の前提が成り立たず、Bridge テストが再バインドの経路を検証しなくなった
**該当箇所**: `ios/Tests/KsSettingsViewBridgeTests/KsBridgeAccessoryViewTests.swift:317-333` (テスト名と doc コメントは :257-258)
**問題点**: このテストが保証すべき性質は doc コメントにあるとおり「画面外へ出て戻る (accessory の再バインドが起きる) 間、同一 view が例外なく再表示される」である。新しい条件 `headerIsOffscreen` は `contentOffset` を書き換えた時点で真になるため、`awaitCondition` はレイアウト 1 回ののち RunLoop を回さずに抜ける。実測では、UIKit が header を手放すまでに通常の実行機でも約 0.46 秒かかる。したがって「遅い実行機では経路を通らない回がある」どころか、**どの実行機でも経路を通らない**。再バインドを壊すミューテーションに対する検出力が 0 であることも実測した (上表)。exploration.md が A の弱みを受け入れた根拠「2026-09-26 の実行で回収待ちが成立している」は、旧来の待機が RunLoop を約 40 周回した結果であり、新しい待機には当てはまらない。テスト名・doc コメント・待機の説明文 (`先頭 Section header の再バインド`) は再バインドを検証していると主張し続けており、lessons test L-001 (保証したい性質を実経路で検証する) にも反する。
**推奨修正**: 論点1の再決定が必要 (下の選択肢)。実装側で閉じる修正は無い。

選択肢:
1. **使い回しをテスト側の操作で確定させる** (推奨): 位置で画面外を確かめたあと、supplementary の作り直しをテスト自身が起こす。たとえば画面外にある間に先頭 Section の header を reload させるか、`reloadData` 系の操作をする。そのうえで、先頭へ戻したときに「スクロール前と異なる supplementary 実体に ProbeView が載っている」ことを再バインドの遷移証拠として待つ。こうすれば時期を決めるのはテストのコードになり、handbook「何を待機条件に選ぶか」に適合したまま経路を必ず通る。ただし、reload 経由の作り直しが元の「リサイクル」(再利用プールからの取り出し) と同じ製品コードの経路を通るかは、実装時にミューテーションで確かめる必要がある
2. **回収待ちを残し、判定の意味を位置と分ける**: 画面外の判定は位置で行い、そのあと「回収された」ことを別の段として待つ。時期は UIKit が決めるため、handbook の規約に反する (却下済みの案 B に近い)。遅い実行機での誤失敗も残る
3. **経路の検証を諦め、テストの主張を実態に合わせる**: テスト名・doc コメント・待機の説明文を「画面外へ送って戻しても同一 view が表示され続ける」に改め、リサイクル後の再バインドは未検証であることを受け入れる。UI 側の兄弟テスト `test_スクロール再利用をまたいでも同一viewインスタンスは復帰する` は UI 層の経路を別の信号で見ているが、Bridge 経路ではその信号が出ないことを実測したため、代わりにはならない

### 🟠 Major UI 診断テストのスクロール往復が使い回しを経由せず、「再表示される」待機が操作前から成立している
**該当箇所**: `ios/Tests/KsSettingsViewUITests/AccessoryViewDetachDiagnosticTests.swift:173-188`
**問題点**: 指摘 1 と同じ理由で、画面外への待機はレイアウト 1 回で抜ける。header は回収されず (5/5 で非 nil、hidden = false)、スクロール往復で使い回しが起きない。そのため、後続の `先頭へ戻した header supplementary が再表示される` の待機 (`isHeaderSupplementaryVisible`) は、先頭へ戻す**前から**真になっている。これは `ConditionWait.swift` の `awaitCondition` の doc コメントにある契約「操作前には成立せず、非同期反映後に初めて成立する遷移証拠を渡す」に反する「待ったつもり」である。exploration.md は「出現を待つもので変えない」と決めたが、この決定は直前の待機が回収を保証していた前提に立っている。差分は行コメントを「再利用を経由しても解消しない」から「画面外へ送って戻しても解消しない」へ書き換えており、検証範囲が縮んだことを認めながら、決定事項にも deviation にも記録していない。`スクロール往復で旧 view が剥がれるようになった` のアサーションは、使い回しの経路で旧 view が剥がれるようになる回帰を検出できない。
**推奨修正**: 指摘 1 の再決定に合わせる。選択肢 1 を採るなら、同じ手段で使い回しを確定させ、戻したときの待機を「別の実体の supplementary が表示される」など操作前には成立しない条件にする。選択肢 3 を採るなら、スクロール往復の段が何を確かめているのか (使い回しを経由しない往復であること) をコメントとアサーションの文言に明記する。

### 🔵 Suggestion 理由コメントの「hidden のまま」は今回の事象と合っていない
**該当箇所**: `ios/Tests/KsSettingsViewBridgeTests/KsBridgeAccessoryViewTests.swift:289` / `ios/Tests/KsSettingsViewUITests/AccessoryViewDetachDiagnosticTests.swift:42`
**問題点**: 「可視矩形から外れた supplementary を … hidden のまま返し続けることがあり」は、handbook にある行 (`cellForItem`) の例の言い回しを移したものである。発見時の実測 (ProbeView を載せたまま返り続けた) と今回の観測 (待機直後は hidden = false) は、hidden になっていることを示していない。
**推奨修正**: 指摘 1・2 の修正で書き直すときに、「可視矩形の外へ出たあともしばらく返し続け、手放す時期は実行機の速さで変わる」のように、観測した事実の範囲で書く。

## 確認した観点 (指摘なし)

- スコープ: 変更はテスト 2 ファイルに閉じ、製品コードには触れていない。deadline は既定の 3.0 秒のまま
- 位置判定の実装: `layoutAttributesForSupplementaryElement` が nil のときは「画面外ではない」側へ倒しており、誤って成立する方向には崩れない。header は `pinToVisibleBounds = false` (製品コード側) なので、レイアウト上の frame はスクロールで動かない。`bounds` を可視矩形として使う判定は、inset 分だけ保守的 (画面外と判定しにくい側) になる

- コメント規約: 追加・変更したコメントに禁止参照・履歴記述は無い
