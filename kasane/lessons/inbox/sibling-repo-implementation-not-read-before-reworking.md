## ルール文 (候補)

relations の sibling から `overlap` に掛かる知らせを受けて自分側の対応に入るときは、**議論や実装を
始める前に相手の該当実装を読む**。相手が既に解いた問題なら最終形は相手のコードにあり、知らせの本文は
その要約でしかない。読んだうえで構造が違えば自分で設計してよいが、**その判断は相手の形を見てから行う**。

相手の実装を読むことは「そのまま写す」ことを意味しない。読んで分かるのは次のどれかで、いずれも出発点が
上がる: (a) 写せる (b) 構造が違うので写せない (c) 相手の側にも穴が残っている。(c) なら相手宛ての知らせが
生える。

事後判定: 知らせ由来の change の exploration.md に、相手の該当実装 (`../<相手>/<パス>`) を読んだ結果が
上記 (a) / (b) / (c) のいずれかとして書かれている。
