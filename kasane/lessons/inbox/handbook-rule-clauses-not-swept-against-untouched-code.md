## ルール文 (候補)

変更の中で handbook の `kind: rule` 文書を新設する (または既存 rule に条項を足す) ときは、確定の前に各条項を `applies-when.paths` が指す全ファイルへ当て、既存コードの不適合件数を実測して 0 にする。0 でなければ、条項を実態に合わせて書き直す・不適合を同じ change で直す・規約に例外を明記する、のいずれをとるかをオーナーに諮る。本変更が書いた成果物だけで条項を検算すると、規約が accepted になった瞬間に触っていない既存コードが違反になり、以後のレビューが実際には誤った修正を指示する規範層になる。

事後判定: 規約を新設・改訂した change の完了報告に、条項ごとの照合対象 (走査したパスと収集した件数) と不適合件数が書かれている。

[[principle-with-enumeration-not-swept-against-public-surface]] (spec / design の原理 + 具体列挙を適用対象の全走査で検算する型) と機序が近い。違いは、あちらが「列挙の漏れ」で spec 文面上は満たせてしまうのに対し、こちらは規範層が既存コードと**矛盾**するため、成立した瞬間に違反が生まれ、レビューが誤った修正を指示する点。
