## ルール文 (候補)

相方 (または任意のレビュー) の指摘を突き合わせで降格する前に、降格根拠と指摘文の双方に含まれる**検証可能な事実主張** (「〜という契約がある」「〜する経路が存在しない」「〜は呼ばれない」等) をコードで確認する。確認せずに使ってよい降格理由は手続き的なもの (deviation 記録済み・重複指摘・スタイルの好み) に限る。「proposal の決定事項・Non-Goal との衝突」は再設計をしない理由にはなるが、**採用済み設計の帰結 (指摘が主張する実害経路) を検証しない理由にはならない**。事後判定: 降格記録 (突き合わせ結果) の根拠文に事実主張が含まれる場合、その検証手段 (該当コード・grep 結果・実測) が併記されている。

## 経緯

- 2026-08-25 investigate-maui-icon-lease-sharing: iOS 共有画像の参照カウント表 (プロセス全域 static) に対し、相方 codex が「リースが破棄されないまま放棄されると画像がプロセス寿命まで強参照される。SettingsView にも恒久離脱時の終端破棄経路がない」と Major 指摘。ホスト (orchestrator) は「実害はリース破棄契約の違反が前提。契約下では残留しない。static 所有は proposal の決定事項で所有権モデル見直しは Non-Goal 却下済み」として降格した。実装ワーカーの「現時点では起票不要」の自己申告と、ホスト側レビューが同じ指摘をしていないことも消極的裏付けにした (アンカリング)。オーナーの「契約違反した呼び出しはユーザー操作で発生するか」という質問を受けてコードを確認した結果: `DisconnectHandler` → `ReleaseHost()` は設計どおり icon リースを保持し、全破棄する `Disconnect()` は private (接続失敗時のみ)、`SettingsView` は IDisposable でなく終端破棄 API が存在しない — つまり「契約」は利用者に課せず、通常のページ使い捨てナビゲーションで放棄が発生する。変更前は GC/finalizer で回収されたものが、static 表がルートになることで恒久リークへ悪化する退行だった。grep 一発で確認できる事実主張を、手続き的理由 (Non-Goal) を先に立てて未検証のまま採否を決めたのが根因。
