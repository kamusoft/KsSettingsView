## ルール文 (候補)

`set -e` / `set -euo pipefail` を前提にした script の自己テストで、検査対象の関数を `if ( ... )` や
`&&` の条件部から呼ぶときは、**その検査が本番の呼び出し文脈 (`main` の経路から素のコマンドとして
呼ぶ形) の挙動を代表しているか**を確かめる。条件部とサブシェルでは errexit が抑止されるため、本番では
代入の時点で終了する経路が検査では先へ進み、**本番に到達しない分岐や、本番には届かない値を前提にした
実装が緑のまま通る**。

失敗を終了ステータスで伝える関数を持つなら、実装側を errexit の効き方に依存しない形 (失敗を状態値で
返し、致命かどうかは呼び出し側が決める) にしたうえで、本番と同じ文脈の写しで 1 本検証する。検査の側を
`( set -e; ... )` で張り直す対処は採らない — bash 3.2 では errexit が再武装されず、新しい bash と
挙動が割れる。

事後判定: 失敗し得る照会・待機の関数について、自己テストが緑であることに加えて、**本番と同じ呼び出し
文脈で成否を測った証跡**が change 配下にある。
