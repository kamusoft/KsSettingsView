## ルール文

デルタスペックの Requirement が外部の決定を参照して「確定済みの値と一致する」形の契約を書くときは、参照先 ADR の `status` を確認する。`proposed` の決定は当該フェーズの外で確定するため、値そのものへの一致ではなく **文書間の一致** や **暫定値であること** を契約にする。

`proposed` の決定同士のずれは「矛盾」ではなく未確定であり、それを解消する整合作業を当該フェーズのスコープへ引き込まない。どのフェーズで確定するかはロードマップが定めており、確定前の値は仮のまま進めてよい。

事後判定: spec に「確定済み」「正の値と一致」等の表現がある場合、参照先 ADR の `status` が `accepted` であることが確認されている。`proposed` を参照する契約は、値ではなく一致・暫定性を対象にしている。
