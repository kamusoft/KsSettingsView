## ルール文

実機検証ハーネスの結果を合格判定に使う前に、**修正前ビルドに対して同一手順で走らせ、想定した壊れ方が再現することを確認する**。ハーネス側の欠陥は「全 FAIL」「全 SKIP」「全 PASS」のどの形でも出て、修正の効果と区別がつかない。特に、試行間で対象の状態を初期化しないハーネスは、対象要素の入力上限・レイアウト変化・IME 設定といった実装と無関係な要因で結果が一様に倒れる。

## 経緯

- 2026-08-11 fix-entrycell-writeback-caret-race: `repro-burst-loop.sh` による Pixel 6a 実機試験で、修正版にもかかわらず 3 種類の偽陰性・偽陽性が出た。
  1. **IME 言語の取り違え**: Gboard が日本語のままで `input text abcde` がローマ字変換され (`あｂｃで`)、20/20 FAIL。exploration が交絡なし条件として指定していた English qwerty を確立していなかった。
  2. **maxLength 飽和**: 対象にした名前欄は `maxLength = 20`。ハーネスが試行間で値を初期化しないため 2 試行で上限に達し、以降は「注入しても値が伸びない」= FAIL として計上された。修正前・修正後の双方が**ちょうど 20 文字**で停止したことから飽和と特定し、上限のないメール欄へ切り替えた。
  3. **対象要素の画面外スクロール**: MAUI では `KEYCODE_MOVE_END` がリストの縦スクロールを誘発し、対象欄が uiautomator の可視ツリーから消えて 20/20 SKIP。右端タップでキャレットを末尾に置く方式へ変更して解消。
- 判別に効いたのは修正前ビルド (`git checkout` で HEAD へ戻してリビルド) との A/B。native 10/18 破損 → 0/17、MAUI 7/18 破損 → 0/18 という同一条件の対比が取れて初めて、修正後の「破損 0」が意味を持った。A/B なしでは 1. と 2. を「修正が効いていない」と誤判定し、3. を「検証不能」と報告するところだった。
- なお `repro-burst-loop.sh` の判定強化 (FAIL > 0 / 有効試行不足で非ゼロ終了) は 2. と 3. をいずれも非合格として正しく落としており、**誤合格は起きていない**。問題は誤って落ちた原因の切り分けであり、A/B がその手段になる。
